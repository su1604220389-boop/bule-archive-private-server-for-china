## 3. 两个真 bug（**已由 `patch_relay_fix` 修复并上线，02:34**）

### Bug 1：转发的协议号被拼错

```
Shittim 实测收到：190044 / 900111 / 350033 / 160000
应该是：          19004  / 90011  / 35003  / 16000
规律：协议号 + 末位数字（4 个样本全是 5 位协议号 ⇒ 残留 1 位）
```

**根因**：`rl_request_json()` 里 `'{"Protocol":%d' % int(num) + text`，假设 `text`（`decoded['fragment']`）以 `,` 开头；实测某些协议的 fragment 开头残留了协议号的最后一位数字。

**修法**：候选拼法逐个试，取第一个能解析且 `Protocol` 等于目标值的结果；全失败就放弃转发（不猜）。

### Bug 2：`Session expired or invalid` 后不重试

Shittim `SessionKeyService.cs:153` 反复抛，桥继续用死缓存。

### ⚠️ Bug 2 的直接成因是**我自己造成的**

`02:13:23` 我让 `srv-ops` 跑探针 `python3 -c "A.ensure_session({})"`。那个探针在独立进程里带空缓存，**重新铸了一个 session 并按 `UserId=2` 覆盖进 `sessions.json`**，把线上桥缓存的 token 顶掉了。之后的 `Session expired or invalid` 全来自这里。

**⇒ 规矩（写死）：绝不在线上桥运行时用探针调 `ensure_session`。要探测就 `touch /www/wwwroot/bapatch/cn_bridge_force_reauth.txt`，让桥自己重铸。**
