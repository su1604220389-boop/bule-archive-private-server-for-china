4. 旧进程的环境变量在 kill 前没来得及完整抓取（`/proc/<pid>/environ` 已随进程消失）；只能确认新进程无 `CN_*` / `BA_*` 覆盖。
5. `--selftest` 跑的是 `_bridge_ref` 基线（46,568 B），**不是线上这份 73,445 B**，覆盖价值有限 —— 真正的可逆性证据来自 §4.2 的「线上文件临时副本彩排」。

## 5. 补丁链兼容性（已验证，别再查）

### 5.1 为什么 5 个后续补丁都兼容

`patch_24000_v3` 只做两件事：

1. 在 **L510**（`SESSION = Session()` 之后）**净插入 551 行**托管块（L510–1060）；
2. **局部替换** 24000 分支。

它**没有**重命名、没有去缩进、没有动 `if num == 90004:` / `if num in (1019, 1017):` / `if proto_int:` / `class Handler` / `want_decrypt` 这些下游锚点。
⇒ **5 个后续补丁的锚点在 v3 之后的 73,445 B 文件里逐个仍然「恰好出现 1 次」，零失效**【实测】。

### 5.2 完整序列（已实测跑通）

```
requestid(→ 9,778)   [改的是 cn_wire.py，与 bridge 无关]
   → v3           73,445
   → 90004        79,681
   → 1017         82,334
   → 8000         93,108
   → simple      107,595
   → preempt     115,738
```

> **全序列复跑 sha 不变**【实测】（`verify_sequence.py`）。

### 5.3 字节数口径警告：76,098 ≠ 82,334

**线上当前文件 = `v3 + 1017`（跳过了 90004）**，所以是 **76,098 B / 1,834 行**。
§5.2 里的 **82,334 B** 是「v3 + 90004 + 1017」的全链值。

两者相差 6,236 B（正好是 90004 那一步的增量）+ 行数差 166 行。**这是正常的，不是补丁没打对。**

另外：`8000 / simple / preempt` 三步的字节数**含脚本写入的绝对路径字符串**，数字随部署路径浮动（参考沙箱 115,738 B vs 线上路径预测 **115,596 B**）。看到 115,596 别以为缺了什么。

### 5.4 关键陷阱：打了 preempt 反而会把请求拦死【实测】

`patch_preempt` 默认 **off**。但一旦 `cn_bridge_exp.txt = decrypt+plain+http200`（**当前就是这个值**），path A 会把**能解密成功的请求直接代理给 Shittim 并 `return`**。

而 `24000 / 8000 / 1017 / 90004` 的新分支**全都在 `_generic_protocol_response()` 里** —— path A 先 return 了，它们永远轮不到。

⇒ **当前策略：不碰 preempt。** `cn_preempt.txt` 不存在 = 正确状态。
⇒ 谁要是"顺手打开 preempt 试试"，会表现为「所有新分支一起失效」，极难排查。

| # | 直觉 | 事实 |

### 9.1 三条回滚路径
