## §2 假支付可行性（Q1/Q2/Q3）

### Q1 不改 `ba_sni.conf` 劫持支付域名 → **技术上做不到**
`ba_sni.conf` 结构（原文）：
```nginx
stream {
    map $ssl_preread_server_name $ba_host { default $ssl_preread_server_name; ... }
    map $ssl_preread_server_name $ba_port { default 443; ... }
    server { listen 443; ssl_preread on; proxy_pass $ba_host:$ba_port; }
}
```
理由：
1. **nginx stream 层按 `listen` 地址:端口匹配 server 块，不按 SNI 匹配**；同一 `443` 上再加 `server { listen 443; }` 只会与现有块**冲突**（实际命中哪一个不确定），**不能**用来做 SNI 分流。
2. 要做 SNI 分流**只能改 `ba_sni.conf` 里的 map** —— 即项目的红线。
**⇒ 结论：Q1 放弃。**

### Q2 `29000` 成功 → 客户端回调 `29001` → **实测走不通**
真实流量（非源码推断）：
```
20:00:51 /api/billing/transactionstartbyyostar  ShopCashId=1597 → 200/448
20:01:02 同上 1597 → 448
20:01:03 同上 1597 → 448
20:01:05 同上 ShopCashId=1600 → 448
此后到 20:02 全是 purchasefreeproduct / purchaseList
全历史 Billing_TransactionEndByYostar(29001) 出现次数 = **0**
```
**⇒ 客户端在 29000 之后不发 29001，而是直接拉起本地 Yostar SDK（`open.yostar.net` / `sdk-api.yostar.cn`，passthrough 真实外网）。**
