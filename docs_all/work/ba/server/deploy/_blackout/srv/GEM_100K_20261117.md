### 1-5 为什么 1M 没到账（**推断 + 源码旁证，未证实**）
`Commands/CurrencyCommand.cs:64` 有一条关键注释：
```csharp
// Gem is derived (Gem = GemBonus + GemPaid, recomputed by UpdateGem on every parcel update),
// so a direct Gem write would be discarded; set the sources.
```
**⇒ `Gem` 是派生值，每次 parcel 更新会用 `GemBonus + GemPaid` 重算覆盖。**
**推断**：邮件领取时若把 1,000,000 直接写进 `CurrencyTypes.Gem`（4）而不写 `GemBonus`，随后 `UpdateGem()` 会把它重算覆盖掉 —— 这与"邮件被收走、GemBonus 只 +45"完全吻合。
**证据等级：推断（有源码注释支持，但未抓 Mail_Receive 内部的 ParcelResult 逐字段验证）。**
**建议的验证方式**（不改代码）：再发一封 **1,000** 的小额邮件，领取后看 `GemBonus` 是否 +1000。若小额也丢 ⇒ 结论成立，需要修 Shittim 的邮件领取路径（把 Gem 映射到 GemBonus）。
