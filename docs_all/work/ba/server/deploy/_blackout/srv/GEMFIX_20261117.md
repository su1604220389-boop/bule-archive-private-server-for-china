# 追加第三节（21:53）：`Shop_BuyAP` 不扣青辉石 —— 根因与补丁

## A) 结论一行

**`Shop_BuyAP` **有**扣费代码，但它写的是派生字段 `CurrencyDict[CurrencyTypes.Gem] -= cost`；而服务器上任何一次 `UpdateGem()` 都会把 `Gem` 重算回 `GemBonus + GemPaid`，于是扣费被"自动撤回"。**
**⇒ 修法：`Gem` 作为 cost 时改走 `SubtractGem()`（它从 `GemBonus/GemPaid` 扣并重算），与全局一致。**

## B) BuyAP 扣费链路（`ShopHandler.cs:716-836`，原文）

### ★ 关键：为什么"扣了又回来"
```
BuyAP 只写 CurrencyDict[Gem]，不调用 UpdateGem → 当次保存里 Gem 看起来是减了；
但之后任何一次 parcel 更新（Mail_Receive / 任务奖励 / 活动 / 商店其它购买…）都会走
ParcelResolver.UpdateAccountCurrency → UpdateGem() → CurrencyDict[Gem] = GemBonus + GemPaid
⇒ 扣掉的数量被重算抹平，表现成"买体力不扣钻"。
```
**⇒ 与"邮件发 Gem 丢失"是**同一个根因的两个方向**：`Gem` 是派生字段，谁直接读写它谁出错。**

## E) 补丁 3：`BAPATCH-BUYAP v1`（`ShopHandler.cs`，原 789-793）

```diff
-        accountCurrency.CurrencyDict[costCurrency] -= costAmount;
-        accountCurrency.UpdateTimeDict[costCurrency] = account.GameSettings.ServerDateTime();
-

+            accountCurrency.UpdateTimeDict[costCurrency] = buyApNow;
+        }
+
+        accountCurrency.CurrencyDict[rewardCurrency] += rewardAmount;
+        accountCurrency.UpdateTimeDict[rewardCurrency] = buyApNow;
+        accountCurrency.UpdateGem(buyApNow);
+        // <<< BAPATCH-BUYAP v1 END <<<
```

**安全性**
- `SubtractGem` 内部：余额不足抛 `AccountCurrencyCannotAffordCost`（但前面 773 行已先判过，正常不会触发）；扣费从 `GemBonus`/`GemPaid` 按来源扣，再 `UpdateGem()` 重算 ⇒ 与"商店其它购买/抽卡"完全同路。
- `rewardCurrency`（AP）不是派生值，`+=` 保持原样。
- 非 Gem 的 cost（若将来数据改成别的货币）走 `else`，与改前一致。

## F) 三处改动的相互影响（重点）

| 场景 | 改前 | 改后 |
|---|---|---|
| 邮件/任务发 Gem（parcel id=4） | 写 `Gem` → 被 `UpdateGem` 抹掉 → **丢失** | 写 `GemBonus` → 重算 → **Gem +N** ✅ |
| 买体力扣 Gem | 写 `Gem` 减法 → 下一次 `UpdateGem` 抹回 → **不扣** | `SubtractGem` 从源字段扣 → 重算 → **真扣** ✅ |
| 抽卡/其它商店扣 Gem | 走 `SubtractGem`（本来正确） | 不变 ✅ |
| GM `/currency 4 N` | 写 `GemBonus/GemPaid` 再重算 | 不变 ✅ |
| AP 满时购买 | 抛 10006（日志 ERR，HTTP 200） | 不变（本次不改） |
| 邮件异常时 | 邮件先删、奖未发 → 丢信 | 先发奖后删 → 原子 ✅ |

**⇒ 三处改动方向一致：把"写派生字段 Gem"全部改成"写源字段/走 SubtractGem"。彼此不冲突。**
**⚠ 唯一需要留意的交互**：`BAPATCH-GEMGRANT` 让发放走 `GemBonus`，`BAPATCH-BUYAP` 让消耗走 `SubtractGem`（优先扣 `GemBonus`）—— 两条都在同一对源字段上操作，语义自洽（先扣免费钻、再扣付费钻的既有规则不变）。
