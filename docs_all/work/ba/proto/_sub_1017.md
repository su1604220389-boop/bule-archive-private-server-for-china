## 1. 七个重点问题的答案

### Q1 1. EquipmentItemListResponse.EquipmentDBs[] 是不是 EquipmentDBSchema？UniqueId 与 ServerId 谁是静态 id？

是。**UniqueId = 静态装备图鉴 id → EquipmentDBSchema.Id（54/54（唯一行 54，表内去重 191））**，同值也 1:1 命中 EquipmentStatDBSchema.sql:EquipmentId（54/54（唯一行 54，表内去重 191），两表 id 集完全相同），另在 RecipeSelectionGroupDBSchema 里 ParcelType=3 的行上 49/54（唯一行 46，表内去重 1123），缺 5 个 命中，坐实「装备 id」语义。**ServerId = 玩家装备实例 id**：84 条互不重复且 全库 0 个槽位都查不到 84/84 个值 → 服务器发号，ExcelDB 里没有。BoundCharacterServerId 同理（全库 0 个槽位都查不到 30/30 个值）。Type=3 是 proto 枚举 ParcelType.Equipment，不是表字段。

### Q2 2. CharacterGearListResponse.GearDBs[] 是不是 CharacterGearDBSchema？

**无法证实（未找到）**：官方样本 GearDBs=[] 元素数为 0，没有任何值。库内确有 CharacterGearDBSchema（104 行，Id 样本 [200000, 200001, 200100, 200101, 200200, 200201]）与 CharacterGearLevelDBSchema（1 行），但按「必须值匹配验证」的口径只能记 not_found / 待补样本。

### Q3 3. MemoryLobbyListResponse.MemoryLobbyDBs[] 是哪张表？

MemoryLobbyDBSchema。MemoryLobbyUniqueId=13010 → 1/1（唯一行 1，表内去重 258） 命中 sql:Id，该行 f4="LobbyYuuka"、图标 Lobbyillust_Icon_Yuuka_01，与该账号 CharacterId 13010 同人；表 258 行（Id 10000…26015）。但只有 1 个元素 → 值证据只能到「弱」，置信度中。Type=8 是 ParcelType.MemoryLobby。

### Q4 4. MomoTalkOutLineResponse / ScenarioListResponse.ScenarioHistoryDBs[] 落哪张表？

**对不上 ItemDBSchema，也对不上 ParcelType=5。对的是 CurrencyDBSchema.ID**：CurrencyDict 的 key 恰好是 1..29 共 29 个，CurrencyDBSchema 整表也只有 29 行、ID=29，29/29（唯一行 29，表内去重 29）；f4 给出货币名（1=Currency_Icon_Gold、2/3/4=Gem、5=AP/Stamina、6=AcademyTicket、18=MasterCoin、24..27=EliminateRaidTicketA..D…）。反证：ItemDBSchema（1803 行）里根本没有 id 4/5/6/14…22 这些值（只有 [1, 2, 3, 7, 8, 9, 10, 11, 12, 13, 23, 30]），且它 f3 恒为 3、不是 ParcelType 列 → 货币不在 ItemDBSchema。CurrencyDict 的 value 才是玩家余额（1=28242189、3=4=5438、5=962…）。

### Q6 6. StickerListResponse.StickerBookDB / AttachmentEmblemListResponse.EmblemDBs[] 对应表？

### Q7 7. EventContentPermanentListResponse.PermanentDBs[].EventContentId → EventContentSeasonDBSchema？

## 5. 做私服时的结论（可直接照抄）

1. **装备**：`EquipmentDBs[]` 行 = `{Type:3, ServerId:<实例id>, UniqueId:<EquipmentDBSchema.Id>, StackCount, Level?, Tier?, BoundCharacterServerId?, IsNew, IsLocked}`。UniqueId 查 `EquipmentDBSchema` 取图鉴数据；ServerId 自己发号（84 条样例 24345882…25520527，互不重复）。
2. **货币**：`CurrencyDict` 必须把 **29 个 key 全部填上（含 10 个 0）**，key 就是 `CurrencyDBSchema.ID`；`UpdateTimeDict` 只对非零/有变化的货币发时间。
3. **剧情**：`ScenarioHistoryDBs[].ScenarioUniqueId` = `ScenarioModeDBSchema.ModeId`；`ScenarioGroupHistoryDBs[].ScenarioGroupUniqueId` = `ScenarioScriptDBSchema.GroupId`。两者不要混用 id 空间。
4. **常驻活动**：`PermanentDBs[]` = `EventContentArchiveBannerOffsetDBSchema.EventContentId` ∩ 已在 `EventContentSeasonDBSchema` 里出现的 id（本包正好 22/25）。
5. **子回包信封**：26 个子回包内部的 `Protocol/SessionKey/ServerTimeTicks/ServerNotification/RequestId` 官方**全部填 0/空**（132/132 字段），真值只在顶层信封 → 私服回包可以照抄 0。
6. **玩家 id 空间**：`AccountServerId/AccountId`(10015354380)、`ClanDBId`(27353)、`CharacterDBId`(3002866)、装备 `ServerId`、`BoundCharacterServerId`、`CurrentRank`(13720) 在 ExcelDB **全库 0 槽位** → 全部由服务器发号，别去表里找。
