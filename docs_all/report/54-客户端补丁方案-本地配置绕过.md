## 0. 结论摘要（先看这 8 条）

1. **`LocalizeConfig.txt` 的解析逻辑找到了，但是它只有 3 个 key，没有第 4 个。**
   全文件 38 MB × 全部 256 个单字节 XOR key × ASCII+UTF-16 双形态扫描，**字面量只有**：
   `Env=dev`、`IsLocalize=false`、`ResUrls=`、`/LocalizeConfig.txt`。
   **没有** `ApiUrl` / `ServerUrl` / `Gateway` / `AuthUrl` / `DevUrl` / `ProdUrl` / `Hosts` / `SkipLogin` / `Bypass` 之类的 key（全部 0 命中）。

2. **`Env=dev` 不是「认证服务器地址开关」，也是官方默认值。**
   客户端二进制里**根本没有任何生产域名/生产 CDN 的字符串**：`gsqc-api`、`state-api`、`bluearchive-cn`、`static.bluearchive-cn.com`、`prodm39` 在 metadata 与 `libil2cpp.so` 里**全部 0 命中**（256 key 全扫）。
   唯一的硬编码 URL 字面量是 **测试环境** `["http://test-ba.yostar.net:5210/api/state" ×3]`（@`0x000C1732`，key `0xB5`），与 report/11 的旧结论一致 —— 这条同时也证明了我的扫描器是对的（已知事实被复现）。

3. **`ResUrls` 才是唯一「有副作用」的 key，而且它是资源 CDN 根，与登录/网关完全无关。**
   社区反和谐就是改它（外网 3 条来源 + 我这边 3 条独立字面量相互印证）。改它 → 客户端**重新下载约 130 MB 资源** → 立绘/文本恢复。改错 → **卡死在资源初始化、进不去游戏**。

4. **⇒ 这条路走不通「跳过登录」。** 三个原因都写在第 8 节：
   ① key 集合里没有任何服务器地址/鉴权开关；② 客户端没有生产 URL 字面量，服务器地址唯一来源是 `GET /api/state` 应答 + `files/Hosts` 缓存；③ 登录状态机 `LoginTask` 卡在 `HttpGameSession.WaitForRequest` 的 `IsFinished` 永不置位（report/48 定案），与本地配置无关。

5. **但这条路有「另外一个」真价值，而且很值钱：`ResUrls` 是一次零风险的 CDN 接管。**
   把 `ResUrls` 指向我们自己的 **HTTP**（不需要 TLS、不需要自签证书、不需要 DNS 劫持、不需要改包），客户端就会从我们服务器拉 `AssetBundles` / `TableBundles` / `MediaPatch` / `Catalog`。这意味着**反和谐资源、自定义表包都能由服务端直接供给**，绕开了 report/10 里那一整坨证书/网关难题。第 9 节给方案。

6. **全机本地配置文件已经全部盘清（第 7 节，13 个文件 + 86 个 key）**，其中**唯一被证明「改了立刻生效」的客户端配置是 `assets/SDKConfigSettings.json` 的 `sdk_url`**（这是 APK 内的，不是 `files/` 里的）。

7. **另外挖到一个真正的「本地开关」候选（第 10 节）**：`GameSessionManager` / `HttpGameSession` 上有 `IsGatewayBypassed`（get/set + backing field 齐全），语义是**传输层绕开网关直连 REST**。它不是鉴权开关，但可能是把 `gsqc-api` 网关这一整层去掉的钥匙。**尚未验证取值来源**。

8. **诚实的失败项**：`LocalizeConfig.txt` 的 **读取点函数级定位没做成**。IG5 在 270 MB / 64 万函数的 il2cpp 上分析预算 138.7 s 到期（`partial=true`），且 il2cpp 代码里函数名全是无名 `sub_`，名字过滤不可用；而该文件的所有字面量在 metadata 里，代码里一个字面量都没有（`ig5`+`strings` 双证 0 命中）。**这是工具预算问题，不是「不存在」**。我已经用 metadata 侧的证据把「谁能读、读了什么」逼到只剩一种解释（第 4 节）。

## 1. 这道题的拦路虎：metadata 的字符串混淆

`global-metadata.dat` 的字符串堆**不是明文**。直接 `strings` 或 `grep -i protocol` 会 0 命中，原因不是"没有"，而是混淆规则：

| 现象 | 原因 |
|---|---|
| 空格（`0x20`）变成 `\x00` | 0x20 这一段用 **整串 XOR 0x20**（大小写翻转）→ 空格变 NUL，字符串在 `strings` 里被切断 |
| 下划线（`0x5F`）变成 `0x7F` | 同上，XOR 0x20 之后 `0x5F^0x20 = 0x7F`（DEL） |
| 大写变小写、小写变大写 | 同上，纯字母看着仍"像字"，但 `grep -i Protocol` 必失败（`pROTOCOL`） |
| **相邻两个字符串需要不同的 key** | ★ **本报告的新发现**：字符串堆是 **「每个字符串各自一个随机单字节 key」**，不是全文件一个 key |

**实测到的 key 分布**（同一区域相邻）：`0x00`（名字表，明文）/ `0x20`（大小写翻转）/ `0x01` / `0x0E` / `0x66` / `0x83` / `0x8B` / `0x8C` / `0x9B` / `0xAA` / `0xAD` / `0xB5` / `0xBA` / `0xBF` / `0xD4` / `0xD7` / `0xE9` …

⇒ **任何"关键词 0 命中"的旧结论都要重扫**。本报告用的是「差分法一次扫完 256 个 key」，不需要猜 key：

> 若存在单字节 key 使 `file[p+i] = needle[i] ^ key`，则 `d_i = file[p+i] ^ needle[i]` 对所有 i 恒等，`key = d_0`。
> 所以取 `d0 = arr[p] ^ needle[0]`，逐位置比 `arr[p+i]^needle[i] == d0` 即可，一次扫完 256 个 key。

配套的第二条判据（用于确定字符串边界）：

> 明文里的 `\0` 就是字符串结束符，但它**不一定**被 XOR。实测有些串的终止符保持 `0x00`、有些变成 `key`。
> 所以边界判定用「解码后可打印性」而不是「找 key 字节」，并且用**加权评分**（字母/数字/空格 +3，常见标点 +1，反引号 `^ | ~ \ $` −6）来压制"偶然可打印"的长 run。

## 3. `Env=dev` 到底改变了什么？

### 3.1 已经能钉死的（确证）

- `Env=dev` 是**客户端自己的默认值**，不是我们改出来的：`work\ba\audit\api-probe.md`（2026-11-11 10:21 首次只读取证）里就已经是 `Env=dev`，而本项目所有改配置实验都在 11-13。
- `Env=dev` **不切环境**：设备上一直是 `Env=dev`，客户端仍然连生产 `gsqc-api`（report/14:379-380、INDEX #67）。
- `Env` 的**取值域在二进制里找不到枚举依据**：`dev` 作为独立字面量只有 1 处（`0x2CF230`，key=`0x00`，语境与配置无关）；`prod` / `test` / `stage` 同样各只有 1 处且都在无关语境（.NET/BCL 词表）。**没有** `Env` 的 switch 表。

### 3.2 最自然的解释（推断·强）

`Env` 与 `ResUrls` 是**同一套 CDN root 机制的两个入参**，理由是数据侧的强对应：

| `LocalizeConfig.txt` | `GET /api/state` 应答字段 | 承载类（metadata 偏移） |
|---|---|---|
| `ResUrls`（3 条，`;` 分隔） | `AddressablesCatalogUrlRoots`（3 条） | `0x00129D6F` / `0x00129D8F`（get/set） |
| — | `CDNLineCount` | `0x0012A118` / `0x0012A129` |
| — | `AssetBundlesUrlRoots` / `TableUrlRoots` / `TableManifestUrlRoots` / `MediaUrlRoots` / `MediaManifestUrlRoots` / `PatchUrlRoots` / `PatchCatalogUrlRoots` / `BundlesCatalogUrls` / `AddressCatalogUrls` / `BundlesHashUrls` | `0x00129EBC` … `0x0012A0FF` |
| — | `InitResPaths` / `GetAssetBundlesUrlRoot` / `GetTableUrlRoot` / `GetMediaUrlRoot` / `GetTableManifestUrlRoot` / `ResetApiUrl` | `0x0012A1BE` … `0x0012A261` |

**三条 static 域名 = `CDNLineCount = 3`**，这是硬对应。
而 `prodm39` 在二进制里 **0 命中** ⇒ 它不是一个能被客户端拼出来的字符串，**它是 `/api/state` 下发的一条 path 段**。
⇒ **`Env` 不可能靠拼字符串把请求打到别的主机**，它要么是"把当前环境标签记下来回显给服务端/埋点"，要么是在一组**已经下发的** root 里做选择（例如挑第几条 CDN 线）。

### 3.3 结论

> **`Env=dev` 没有任何可以指向别的服务器的能力。它是官方默认标签。改它 = 改一个被记录/回显的字符串。**
> 这解释了为什么 report/14 的排除实验以"仍是 gsqc-api"告终，也解释了为什么社区所有反和谐教程里 `Env` 恒为 `dev`、没人碰它。

## 4. 客户端是怎么读这个文件的？（读取点定位，含失败说明）

### 4.1 已确定的骨架

- **路径**：字面量是 `/LocalizeConfig.txt`（**带前导 `/`、不带目录**）⇒ 代码是 `某根路径 + "/LocalizeConfig.txt"`。
  同区（`0x393xx`–`0x396xx`）还并列着 `/TableBundles/`、`/AssetBundles/`、`/Android_PatchPack/catalog_Android.zip`、`/Windows_PatchPack/`、`/iOS_PatchPack/`、`/catalog_` —— **这是一个「路径拼接表」区**，`/LocalizeConfig.txt` 与资源路径是同一批、同一种写法 ⇒ 它的根是 `Application.persistentDataPath`（即 `files/`）。
- **格式**：`key=value` 逐行、`;` 分隔多值、无 section/无引号（设备实测 3 行 164 B）。
- **读 vs 写**：`ResUrls` 有 **两条**字面量（`ResUrls` 和 `ResUrls=`），`Env`/`IsLocalize` 各只有一条**带值的**（`Env=dev`、`IsLocalize=false`）。
  最自然的解释：**`ResUrls=` 用于写（模板），`ResUrls` 用于读（key 名）**；`Env=dev` / `IsLocalize=false` 是写默认值用的整行模板。

### 4.2 为什么代码侧定位失败（诚实标注）

| 尝试 | 结果 | 说明 |
|---|---|---|
| `ig5_open` `libil2cpp.so`（270 MB） | ✅ 打开成功，**645,735 函数**，`analysisProfile=interactive`，耗时 **138.7 s**，`partial=true`（分析预算到期） | 库能开，但预算不够 |
| `ig5_funcs --filter ocalize` / `--filter GameConfig` | ❌ `worker 不在运行` / `worker 已被关闭` | 270 MB il2cpp 的 worker 被回收；且 il2cpp 函数名是无名 `sub_`，**名字过滤本来也不可用** |
| `strings libil2cpp.so` 全量扫 `Localize` / `IsLocalize` / `ResUrls` / `prodm39` | **0 命中** | 这是**正确**的阴性：IL2CPP 的字符串字面量**只存在 metadata 里**，`.so` 里没有（对照组：`test-ba.yostar.net` 在 .so 里也是 0，在 metadata 里有） |
| 读 `libil2cpp.so` 里的 metadata usage 表 | 未做 | 需要 IL2CPP 元数据 usage 解析器（Il2CppDumper 级别工作量）；工作区里**没有** `dump.cs` / `script.json` / `il2cpp.h` |
| 按类名找 | **`LocalizeConfig` 作为标识符 0 命中** | ⇒ **没有一个叫 `LocalizeConfig` 的类**。它一定是别的类里的一段静态方法 |

> **这是本次的失败项**：函数级定位没做完。原因是工具预算 + 缺 Il2CppDumper 产物 + 代码里无字面量三重叠加，**不是"这个文件不被读"**。
> 下面 §4.3 是现有证据能支持的唯一自洽模型。

### 4.3 自洽模型（推断·强）

```
① 冷启动 → GameMain.InitApp → 读 files/LocalizeConfig.txt
       ├ 有 → 解析 Env / IsLocalize / ResUrls
       └ 无 → 用内置模板写一份默认文件（Env=dev、IsLocalize=false、ResUrls=）
② ResUrls（若非空）覆盖 /api/state 应答里的 AddressablesCatalogUrlRoots
       → 之后所有 AssetBundles/TableBundles/MediaPatch/Catalog 的下载根都指向 ResUrls
③ 之后整个进程生命周期内不再重写这个文件（设备上 mtime 从 2026-11-13 08:53 至今未变）
```

**支持这个模型的 5 条独立证据**：

1. `Env=dev` / `IsLocalize=false` / `ResUrls=` 三个字面量**恰好等于**设备上文件的三行内容（`Env=dev` 与 `IsLocalize=false` 连"值"都在字面量里）。
2. **`ResUrls` 的具体值（三条 static URL）在二进制里 0 命中** ⇒ 默认模板只写到 `ResUrls=` 为止，值来自运行期 ⇒ 与"从 `/api/state` 的 `AddressablesCatalogUrlRoots` 取"完全吻合，且值与 report/31 取到的官方真值**逐字符相同**。
3. 设备文件的 mtime **从未变过**（三份快照 `c1.txt` / `cfg2.txt` / `pdp.txt` 一致），而同期 `Hosts` / `LocalConfig.json` / `manifest.db` 都在变 ⇒ 它是**一次性写出**的，不是每次启动回写。
4. **社区实验的反向印证**：把 `ResUrls` 改成外网地址 → 客户端**重新下载约 130 MB 资源**（多个独立来源一致）；改成死链 → **卡在资源初始化进不去游戏**（外网上游仓库 README 的 CAUTION 明确写了）。**改一个 `ResUrls` 能让客户端去重下资源，这只能是"它覆盖了 CDN root"**。
5. `report/35:55` 解密出的 `Account_Auth` 请求明文里带 `"ResUrl":"https://static.bluearchive-cn.com/prodm39"`，与 `ResUrls` 第 1 条逐字符相同 ⇒ 客户端把这个根**也用在上报里**（`<ResUrl>k__BackingField` + `get_/set_ResUrl` 与 `SubChannel` / `AccessIp` / `MarketId` 同簇）。

> **必须保留的歧义**：第 5 条不能单独证明 `LocalizeConfig` 被读 —— 因为同一个值也可能来自 `/api/state` 的 `AddressablesCatalogUrlRoots[0]`（两者值完全一样）。**判定实验**见 §11.2。

## 5. `IsLocalize=false` 到底改变了什么？

**坦白说：没有直接证据。** 但有一条**同区字面量**给了最合理的解释。

### 5.1 观测

- `IsLocalize` 作为**独立标识符**在 metadata 里 **0 命中**（`get_IsLocalize` / `IsLocalize` / `isLocalize` 全部没有）。
  ⇒ **它不是一个 C# 属性**，只是一行被读取的文本 key。
- 设备上 `IsLocalize=false` 与 `Env=dev` 一样是**官方默认值**（社区三方来源的"官方原版"配置逐字相同）；所有反和谐教程里 `IsLocalize` 恒为 `false`，**没有任何一份教程说改它能反和谐**。
- 同区（`0x7CA1E`，key `0xD4`，与 `LocalConfig.json` @`0x7C9C5` 仅隔 ~100 B）有一条字面量 **`Localize/InbuildLocalize`**（24 B，确证）。

### 5.2 推断（中）

`Localize/InbuildLocalize` 的形态是 `目录/子目录`，且与 `LocalConfig.json` 挨着 ⇒ 它大概率是**本地化表包的目录**。
⇒ **`IsLocalize` 的作用是在「内置（inbuild）本地化表」与「外部/下载的本地化表」之间切换。**
`false` = 不用内置表（走下载表）—— 这也解释了为什么国服默认 `false`：

- 国服的表包在 `files/TableBundles/`（435 MB / 6,227+ 个包）里，由 `ResUrls` 指向的 CDN 下发，是"外部表"；
- 而"内置表"是打进 APK 的那份（日服/国际服原版）——**这正是社区"反和谐"想拿回来的东西**。

**但这只是推断，不能当结论用**：没有任何一份教程把 `IsLocalize` 改成 `true` 来做反和谐；本报告**不建议**改它（见 §7.1 的建议值）。

### 5.3 与"登录"的关系

**零关系。** `IsLocalize` 只影响本地化表来源，登录链路（`LoginTask` → `Account_Auth` → …）完全不碰本地化表。

## 6. `ResUrls` —— 唯一真正"能动手"的 key

### 6.1 语义（确证）

`ResUrls` = **资源 CDN 根列表**，`;` 分隔，**逐条按行号对应 CDN 线**（`CDNLineCount = 3`）。端口/协议**逐字当 URL root 用**。
它下游覆盖的是这 4 类下载（对应 report/05 从 AzusaBA 侧拿到的符号族，以及 metadata 里的字段名）：

| 类别 | metadata 字段 | 下载内容 |
|---|---|---|
| AssetBundles | `AssetBundlesUrlRoots` / `BundlesCatalogUrls` / `BundlesHashUrls` | `files/AssetBundles/**`（6.5 GB） |
| Tables | `TableUrlRoots` / `TableManifestUrlRoots` / `TableManifestHashUrlRoots` | `files/TableBundles/**`（435 MB / 6,227+ 包） |
| Media | `MediaUrlRoots` / `MediaManifestUrlRoots` / `MediaManifestHashUrlRoots` | `files/MediaPatch/**`（4.0 GB） |
| Patch/Catalog | `PatchUrlRoots` / `PatchCatalogUrlRoots` / `AddressableCatalogUrlRoot`(s) | `catalog_*.json/zip/hash` |

### 6.2 与「登录」的关系（确证：无关）

`ResUrls` 只喂给资源层。**API 主机名/网关名不来自这里**（report/10:33 的定性是对的，只是当年那次实验无效）。

### 6.3 副作用与风险（重要）

- **改对了 → 客户端会重新下载资源**（社区实测约 130 MB；如果本地已被判为过期，可能是全量）。
- **改错了（死链/不可达/证书错）→ 卡死在资源初始化，进不去游戏**（外网仓库 CAUTION 原文警告；report/10 的"网络异常，请重新连接"其实就是这一类）。
- **不支持 `https` 自签证书**：社区样例用的是 **`http://`** 明文，说明 CDN 侧不强制 TLS。我们要接就得用 **`https` + 真证书**（`example.com` 有真证书，见 report/09 D04）**或 `http` 明文**。
- 只影响**资源下载**，**不影响登录是否成功**。

## 8. 为什么这条路**不能**跳过登录（三重硬证据）

### 8.1 key 集合里没有这个能力（字面量级）

`LocalizeConfig.txt` 的全部 key = `Env` / `IsLocalize` / `ResUrls`。
「指定认证服务器地址」「跳过某段逻辑」所需的 key 名在 256 key 全扫下 **0 命中**（§2.1 整张表）。
**一个只有 3 个 key、且其中 2 个连值都写死在字面量里的纯文本文件，不具备承载"鉴权开关"的结构空间。**

### 8.2 服务器地址在客户端里**没有静态来源**，只能来自 `/api/state`

- `gsqc-api` / `state-api` / `bluearchive-cn` / `static.bluearchive-cn.com` / `prodm39` 在 **metadata + libil2cpp.so** 里全部 0 命中（256 key × ASCII+UTF-16）。
- 唯一硬编码 URL = **测试环境** `http://test-ba.yostar.net:5210/api/state`（×3，`0x000C1732`，key `0xB5`）。
- 承载类：`ServerInfoDataRepository`（`get_StateServerUrl` / `GetConfig` / `GetApiServerInfo` / `GetGameServerInfo` / `DownloadServerInfoDataHttp2` / `Servers` / `StateServerResponse`）+ `GameSessionManager`（`get_ApiUrl` / `get_GatewayUrl` / `get_IsLivePublished`）。
⇒ **改本地文本文件无法改变 API 主机**，因为文件里根本没有这个字段，代码里也没有这个字符串。

### 8.3 卡点根本不在"判断"，在"协程永不完成"

report/48 已定案：

- `HandleAccountAuthResponseMessage` @`0x0013FACF` 是**同步方法**（`0x13F600–0x141400` 区间 104 条编译器生成名里**没有** `<HandleAccountAuthResponseMessage>d__N`）⇒ **它本身不会挂起**；卡点不在它里面。
- 真正卡死：`HttpGameSession.WaitForRequest`（`<WaitForRequest>d__59`@`0x0021A802`，条件 `get_IsFinished`@`0x0021A583`）的 `IsFinished` 永不置位 ⇒ Unity 协程 `yield` 一个永不完成的对象，每帧检查、条件永假 ⇒ 零后续请求、无弹窗、无超时兜底（`TimeOut`/`TIMEOUT` 都在 HTTP 层，200 已让 HTTP 正常结束）。
- `LoginState` **只有 `Finished` / `Failed` 两个成员**（`0x0013FDD3`）⇒ **卡住在客户端状态里无处表示**。

⇒ **没有任何"本地开关"能改变这件事**，因为这不是「一个 if 判断的结果」问题，而是「一个回调永远不被调用」的问题。要改只能改**服务端应答**（让会话被正确认领），或**动态 hook**（report/17、38、48 那几条线）。

### 8.4 一句话

> **`LocalizeConfig.txt` 是一个「资源 CDN 覆盖文件」，不是一个「登录配置」。**
> 想在客户端本地绕过登录，这条路在结构上就不存在——不是我们没找到，是它没有这个字段。

## 9. 那么这条线真正的价值：`ResUrls` = 一次零风险的 CDN 接管

这是本报告**唯一建议执行的行动项**。

### 9.1 为什么有价值

| 现状（report/10 的困境） | 改 `ResUrls` 之后 |
|---|---|
| 要给客户端换网关 / 换静态资源，得先过 TLS + pinning + DNS（`/system/etc/hosts` 被 netd 的 mount ns 挡住、单 IP 阻断被 CDN 轮换打地鼠） | **完全不需要**：`ResUrls` 是文件里的明文 URL |
| 反和谐资源要塞进 `files/AssetBundles`（6.5 GB，得替换 `.bundle`，外网 457 star 的仓库就是这么干的，脆弱且整包重下） | **服务端托管**：客户端自己按我们的 CDN 拉 |
| 自定义表包（数值/文案/活动）没法下发给客户端 | `TableBundles` 根可控 ⇒ 表包可控 |
| 要证书 | **用真证书的 `example.com`（report/09 D04 已经定了这个方向）或明文 `http`，都不需要自签 CA** |

**而且它跟登录线正交**：改 `ResUrls` **不会**让登录更糟（登录卡点独立），**也不会**影响我们已经复刻的响应加密。

### 9.2 方案（三档，从最保守到最激进）

| 档 | `ResUrls` 值 | 用途 | 风险 |
|---|---|---|---|
| **A（只读验证，建议先做这个）** | 保持官方 3 条 | 基线 | 0 |
| **B（接管 CDN，最小改动）** | `https://example.com/prodm39` ×3 | 让我们自己的 nginx 供 `AssetBundles`/`TableBundles`/`MediaPatch`/`Catalog` | 中：远端缺文件 → 卡资源初始化（§6.3） |
| **C（反和谐）** | 指向一份"未和谐资源"的镜像根 ×3 | 立绘/文本恢复 | 中：需要完整镜像 11 GB 资源，缺一个就卡 |

> **`ResUrls` 必须给 3 条**（`CDNLineCount = 3`）。社区做法是**同一个 URL 重复 3 次**，这是已知能工作的写法。**不要只写 1 条。**

### 9.3 前置条件（不满足就别改）

1. `https://example.com/prodm39/` 必须真的能返回客户端要的**每一个** catalog / manifest / hash / `.bundle`；
2. 要么用 `https`+真证书，要么用 `http`（**不要自签 `https`**，社区样例用 `http` 正是因为如此）；
3. **必须准备好一键回滚**（官方 3 条 URL 要原样留档，见 §9.5）；
4. 冷启动预期 **45–58 s**，改完首次可能要**额外下载约 130 MB**，不要误判为卡死。

### 9.4 交付：本地生成的两份文件（**只在本地，由另一个 agent 推手机**）

**① 接管版（方案 B）** → `work\ba\cfg\LocalizeConfig.cdn-ours.txt`

```
Env=dev
IsLocalize=false

## 10. 附带发现：一个可能真有关系的「本地开关」

在挖 `GameSessionManager` 时发现（**这是本线的额外产出，不是原任务的答案**）：

```

**语义**：`HttpGameSession` 有两条发送路径 —— `ApiUrl + SendRequestApi`（REST）与 `GatewayUrl + SendRequestGateway`（网关 envelope）。
`IsGatewayBypassed` 就是这两条之间的**显式开关**（report/41:470-476、48:92 已经注意到它，但没人查过取值来源）。

**为什么值得看**：如果它能为 `true`，客户端会**绕开 `gsqc-api` 网关的 packet 信封**，直接走 REST —— 那我们第 37 号报告里辛苦复刻的国服信封加密这一整层就**不需要了**。

**还不知道的**：取值来源、默认值、能否被服务端影响、是否与 `IsLivePublished` 联动。
**建议**：这条要查只需在 `HttpGameSession` / `GameSessionManager` 上做**运行期读字段**（Frida 读 `Il2CppField`），比继续静态挖划算得多。**但不属于本报告范围，仅作线索移交。**

### 11.2 ★ 一次零风险、单变量的判定实验（**建议立刻做，5 分钟**）

**目的**：证伪/证实「`LocalizeConfig.txt` 的 `ResUrls` 真的被读」。
已有的间接证据（§4.3）够强，但缺一条直接因果。

**做法**（不需要动手机也能做，只要有人愿意推一个文件）：

1. 把 `ResUrls` 第 1 条改成 `http://example.com/prodm39`（**明文 http，别上自签 TLS**）；
2. 在 `example.com` 的 nginx 上给 `/prodm39/` 挂一个空目录 + 打开 access_log；
3. 冷启动游戏，**只看两件事**：
   - `access_log` 里有没有 `GET /prodm39/...`；
   - 客户端随后解密出的 `Account_Auth` 请求明文里，`"ResUrl"` 字段是**跟着变成我们的地址**，还是**仍是 `https://static.bluearchive-cn.com/prodm39`**。
4. 判据：
   - 有请求 ⇒ **`LocalizeConfig` 被读，且它就是 CDN root 的覆盖入口**（方案 B 成立）；
   - 无请求但 `ResUrl` 字段变了 ⇒ 被读，但作用点在上报而不在下载；
   - 两者都没变 ⇒ 要么没读到（根路径不是 `files/`），要么被 `/api/state` 覆盖了（那就得先让 `state` 的 `AddressablesCatalogUrlRoots` 为空）。

**这个实验完全不影响登录**（登录本来就卡在别处），失败也不会有副作用。
