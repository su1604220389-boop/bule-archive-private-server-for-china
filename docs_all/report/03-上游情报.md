## 1. Q1｜Shittim-Server 官方 client-patching 文档怎么说

**仓库**：[Neoexm/Shittim-Server](https://github.com/Neoexm/Shittim-Server)（C# / ASP.NET Core .NET 10，465★，活跃至 2026-08-20）【原文】
**文档原文**：[docs/docs/server/client-patching.md](https://github.com/Neoexm/Shittim-Server/blob/main/docs/docs/server/client-patching.md)（最后改动 2026-08-12，commit `15436c0`）【原文】

### 1.1 原文抄录（这是全篇最重要的一段，逐字）

> ## What gets patched
>
> | Patcher | File | What it changes |
> |---|---|---|
> | Metadata | `global-metadata.dat` | the server's RSA public key, in three 150-byte chunks, and the region label |
> | Gamescale IAS | `gamescale.core.dll` | the login endpoint |
> | Inface config | the inface config file | endpoint configuration |
> | Steam offline | `GameAssembly.dll` | off by default; lets the client hand out an external ticket with Steam offline |
> | grap64 | the plugin directory | plugin management |
> | Banners | the client's `ExcelDB.db` | recruitment banner rows |
> | Region label | `global-metadata.dat` | the title-screen region name |
> | Store URL | the client's store lookup | points it at this server so the shop currency check answers with no route out |
>
> The `GameAssembly.dll` patcher is off by default because Steam restores that file on a verify, and a restored file means the patch is silently gone.

> ## The region label
>
> The title-screen region name is not on the wire at all. It is the `ServerRegion` enum member name inside `global-metadata.dat`. **Three things have to spell it identically - the enum member name, the standalone region literal, and the connection group name the server serves - or `Queuing_GetTicket` comes back with an empty gateway URL and the client hangs on the loading screen.**
>
> The same mechanism covers every other client-local string: rows in the client's localization table are keyed by a hash of the localization key, so patching a row is how you change any UI string that never crosses the wire.

> ## Signature matching and client updates
>
> The native patches are **anchored on byte signatures, not fixed offsets**. A Steam auto-update replaces the DLL and silently un-applies every one of them. The symptom in `logs/log.txt` is:
> ```
> IAS binary patch target was not found: <name>
> ```
> When that happens the signature has to be re-anchored against the new binary. A soft "cannot be processed" popup at the payment step, specifically, is the stamp and payment precondition patch having come unstuck.

### 1.2 打的是什么补丁？（源码级确认，比文档更准）

来源：[`Services/ClientMetadataPatchService.cs`](https://github.com/Neoexm/Shittim-Server/blob/main/Shittim-Server/Services/ClientMetadataPatchService.cs)【原文】

**文档说「three 150-byte chunks」，但源码说 272/272/255。源码注释解释了原因：**

> The key is three separate string literals in the metadata rather than one run, and the split lands wherever the build's literal packing put it: **272/272/255 for the RSA-4096 key, and 150/150/150 for the RSA-2048 one it replaced.**

> The official Nexon gateway RSA-4096 public key, exactly as it is embedded inside the client's `global-metadata.dat`. **The client RSA-encrypts the 50001 gateway handshake with this key**, so swapping in the private server's own key is what lets the gateway decode the handshake. **Ours has to be 4096-bit as well**: the chunks are fixed-size holes in `fieldAndParameterDefaultValueData`, and a PEM of any other length cannot go into them without shifting the section and every offset past it.

> The three byte runs are **located by content (an AOB scan)** rather than by fixed file offsets: **the offsets move every time the client is rebuilt, and build 439170 shifted all three by +0x49B0.** Writing at a stale offset corrupts whatever IL2CPP metadata now lives there and **hangs the client at "Unpacking game resources"**. A scan also **fails safe**: a chunk that cannot be found means no write at all.

**⇒ 关键结论：补丁对象不是 URL，是「网关握手用的 RSA 公钥」。** 客户端把 `Account_CheckNexon`(50001) 握手用这把公钥加密；私服换成自己的公钥，私服才能用自己的私钥解开。
**⇒ 时长限制：必须同为 RSA-4096。** PEM 长度必须精确等于 799 字节（272+272+255），否则会把 `fieldAndParameterDefaultValueData` 段及其后所有 offset 全部偏移，直接崩。
**⇒ 落盘形态**：PEM 字符串以 3 段 IL2CPP 字符串字面量分散存放在 metadata 的默认值数据段里（不是连续一整串）。

### 1.3 版本匹配怎么做（这是被反复踩的坑）

| 做法 | 结果 | 来源 |
|---|---|---|
| 硬编码 offset | **必错**。build 439170 三个 offset 全部 +0x49B0，写错 ⇒ 客户端卡「Unpacking game resources」 | 【原文】代码注释 |
| PR #30 硬编码地址修补 | 被 **Closed**（未合并）。PR 描述：「Update client metadata patch addresses to match the current client layout, **fixing gateway payload decode failures caused by incorrect patched metadata**」 | 【原文】[PR #30](https://github.com/Neoexm/Shittim-Server/pull/30) |
| 最终方案：**按内容 AOB 扫，且要求唯一命中** | 唯一命中才写；找不到或命中多处 ⇒ **完全不写**（fail-safe），只记 warning | 【原文】`TryLocateUnique()` |
| 回滚 | 写 `.shittim_patch.json` 边车文件存 original/patched base64；关闭开关时按 offset 校验当前字节==patched 才回写 original，否则拒绝 | 【原文】 |
| 关闭即还原 | 「Turning the patch off is how someone goes back to the official client, so it has to mean **putting the key back** rather than merely not patching again.」 | 【原文】 |

### 1.5 端口与分层（`architecture.md` 原文）【原文】

| 端口 | 用途 |
|---|---|
| 5000 | admin API / dev / GM / **SDK endpoints** / `/health` |
| 5100 | **the gateway the client sends protocol traffic to** |
| 443 | SDK endpoints over HTTPS（`certs/` 有证书时） |

> The client sends everything through one endpoint, **`POST /api/gateway`** on the gateway port. The first exchange, **`Account_CheckNexon` (50001), is RSA**. The server's public key has been patched into the client's `global-metadata.dat` in three 150-byte chunks, and the server decrypts with `Config/GatewayPrivateKey.pem`. **If that private key is missing the handshake fails and the client hangs on "Unpacking game resources"** rather than reporting anything about keys.
>
> After the handshake the session carries an AES key. **In practice the in-session key ends up null on this client, so responses go out as plaintext** — a fact worth knowing before chasing a crypto bug that is really a content bug.

> **对我们可用性**：高。【直接可用】这段「RSA 握手失败 ⇒ 卡 Unpacking game resources」的**症状对照表**，与我们在 ACE 壳下观察到的「认证服务器拒绝了请求」是不同层次的现象，可用来区分「密钥错」与「地址错」。另：**会话 AES key 实际为 null、响应明文**这一条，能省掉大量抓包 decrypt 工作。

### 2.2 BaPs 的安卓 mitmproxy 教程（原文关键段）

来源：[Android_Mitmproxy_Readme_ZH.md](https://github.com/gucooing/BaPs/blob/main/Android_Mitmproxy_Readme_ZH.md)（By 北野桜奈，commit 2025-03-21）【原文】

**重定向脚本（原文，这就是日服的完整主机清单）：**

```python
redirects = {
    "https://ba-jp-sdk.bluearchive.jp": "http://127.0.0.1:5000",
    "https://prod-gateway.bluearchiveyostar.com:5100/api/gateway": "http://127.0.0.1:5000/getEnterTicket/gateway",
    "https://prod-game.bluearchiveyostar.com:5000/api/gateway": "http://127.0.0.1:5000/api/gateway",
    "https://prod-logcollector.bluearchiveyostar.com:5300": "http://127.0.0.1:5000/game/log",
}
```

**启动方式（原文）：**
```bash
mitmweb -m wireguard --no-http2 -s redirect_server.py --set termlog_verbosity=warn --ignore <你的IP>
```

**证书安装（原文要点）：** 把 `mitmproxy-ca-cert.cer` 改名成 **`c8750f0d.0`** → 推到 `/system/etc/security/cacerts/` → `chmod 644` → 重启。**注意：这个方案要求 root（`adb root` + `adb remount` 改 /system）**，属于"系统 CA"而非"用户 CA"。

**故障排查原文两条（很有用）：**
> `Client TLS handshake failed. The client does not trust the proxy's certificate for xxx.com`
> 安卓端安装后证书消失？→ MT 管理器给 SU 权限，去 `/system/etc/security/cacerts/` 找 `c8750f0d.0` 给 664 权限。
> （手机端）无权限修改系统目录？→ 安装证书到**用户证书**，然后**安装模块自动将用户证书转到系统证书**，之后重启。

**⇒ 这最后一条就是「零 root」的现实折中：用户证书 + 一个转系统证书的 LSPosed/Magisk 模块。**
**可信度**：高。【直接可用】脚本可直接改成国服域名。

⭐ **网关重写的原文（决定性的 4 行）：**

> ```python
> # Redirect any connection on port 5100 (game gateway) to our local gateway, regardless of the destination host.
> # This catches the case where the server config has an empty GatewayUrl and the game uses its hardcoded Nexon gateway fallback.
> if flow.request.port == GATEWAY_PORT or (flow.request.pretty_host and ':5100' in flow.request.pretty_host):
>     flow.request.scheme = 'http'; flow.request.host = SERVER_HOST; flow.request.port = GATEWAY_PORT
> ```

**⇒ 三重确认：(1) 网关地址由 server config 下发；(2) 客户端有硬编码官方 fallback；(3) 兜底手段是「按端口 5100 抓」，不管目标域名是谁。**
**⇒ 这一招对我们极有参考价值：如果国服网关也用固定端口，可以按端口兜底，完全绕过"主机名不知道"的问题。**

其它值得抄的细节（原文）：
- **`config.na.nexon.com` 绝对不能 kill**：「gamescale/Inface SDK init gates on this; must be served, not killed.」kill 掉 ⇒ SDK 不初始化 ⇒ Bolt 登录 base URL 永不设置 ⇒ `/signInWithTicket.nx` 永不触发。
- **`platform.gamescale.nexon.com/pcc/gid/` 必须自己回 200**：真机走 HTTP 且回 301→HTTPS，而游戏客户端 **不跟随 301**，于是永远拿不到平台配置，SDK init 卡住。→ 原文内置了一份完整 PCC JSON（`toy_service_id:2079`, `portal_game_code:"1000158"`, `alltem_code:"bluearchive"` 等）。
- **`store.steampowered.com/api/appdetails` 必须伪造**：否则大厅报 "Failed to request prices"（appid **3557620**）。
- **`ngs_x_init_response.bin`**：NGS（Nexon Game Security）`x-init` 响应用一个二进制 blob 直接回放。
- **`/prod/crexception-prop` → `{"propCheck": false, "period": 10, "ratio": 10}`**：崩溃上报的比率开关。
- **OFFLINE_MODE 用 hosts 文件指到 127.0.0.2**，并且「127.0.0.3 is that same server (it binds 0.0.0.0) under an address the guard does not match」——**用不同 loopback 地址规避 mitmproxy 的自转发保护**，是个巧办法。
- **WireGuard 隧道**：注释提到「requests that go out to real Nexon hosts **over the WireGuard tunnel**」——作者也是用 WireGuard 把流量兜住的，与 BaPs 教程同源。

**可信度**：高。【直接可用】

### 2.4 有没有 "patched launcher"？

**没有搜到任何 BA 的 patched launcher 项目。**【摘要 + 搜索缺失】
理由（【推断】）：BA PC 版是 **Steam 发行**，启动器是 Steam 本体，改启动器没有意义；手机版没有 launcher 概念。真正接近"launcher"的是 Shittim 的 **Control Center**——但它不是补丁启动器，而是**安装器**：

> Grab Shittim Control Center from the releases page. It handles the whole setup: **downloads the server, installs the .NET 10 SDK and mitmproxy if they're missing, and trusts the proxy's CA certificate.** When the readiness card says everything is ok, press the start server button, wait for the server to start then launch Blue Archive from Steam.

**⇒ 这是"patched launcher"的现代形态：一键装依赖 + 装 CA 证书 + 启服务。值得抄。**

## 4. Q4｜网关地址在客户端里到底以什么形式存在

**这是全篇第二重要的部分，直接回答我们的卡点。**

### 4.1 结论：**不在客户端里"存着"，而是服务端下发的。**

证据链（三条独立互证）：

**(1) 官方文档明说区域名影响 `Queuing_GetTicket` 返回的 gateway URL**【原文】
> Three things have to spell it identically ... or **`Queuing_GetTicket` comes back with an empty gateway URL** and the client hangs on the loading screen.

⇒ 说明 **gateway URL 是 `Queuing_GetTicket` 这个协议包的返回字段**，服务端想返回什么就返回什么。

**(2) 服务端确实有专门 servlet 下发连接组配置**【原文】
[`Controllers/Api/ServerInfoController.cs`](https://github.com/Neoexm/Shittim-Server/blob/main/Shittim-Server/Controllers/Api/ServerInfoController.cs)：

```csharp
[HttpGet("com.nexon.bluearchive/server_config/{*filename}")]
[HttpGet("com.nexon.bluearchivesteam/server_config/{*filename}")]
public ActionResult GetServerUrl(string filename)
{
    if (!filename.Contains("_Live") || !filename.EndsWith(".json")) return NotFound();
    var serverInfoConfig = Config.GetServerInfoConfig();
    var result = new JObject {
        ["DefaultConnectionGroup"]  = serverInfoConfig.DefaultConnectionGroup,
        ["DefaultConnectionMode"]   = serverInfoConfig.DefaultConnectionMode,
        ["ConnectionGroupsJson"]    = serverInfoConfig.ConnectionGroupsJson,
        ["desc"]                    = serverInfoConfig.Desc
    };
    return Content(result.ToString(Newtonsoft.Json.Formatting.None), "text/plain");
}
```

⭐ **`ConnectionGroupsJson` —— 客户端拿到的是一组"连接组"，每组里有服务器地址。这就是网关地址的真正来源。**
⭐ 请求路径形如 `/com.nexon.bluearchivesteam/server_config/439170_Live_77acRXMErRIj8461BJ0KXJP3t.json`（见 `ServerConfig.ServerInfoUrl`），即 **`{构建号}_Live_{随机串}.json`**。构建号与随机串由客户端自己拼出来 ⇒ **构建号一定来自客户端某个已知的版本字符串**（这就是"版本匹配"的真正含义）。

**(3) 客户端留了硬编码 fallback**【原文，mitmproxy 脚本注释】
> This catches the case where the server config has an **empty GatewayUrl** and the game uses its **hardcoded Nexon gateway fallback**.

### 4.2 所以完整的重定向链条是

```
① SDK 登录     客户端 → sdk 主机（明文 HTTPS，可改配置/证书）
② 版本/连接组   客户端 → server_config/{build}_Live_{hash}.json  → ConnectionGroupsJson
③ 网关握手     客户端 → GatewayUrl:5100 → POST /api/gateway → Account_CheckNexon(50001) RSA 加密
④ 会话         返回 session AES key（实测为 null，响应明文）
```

**⇒ 要在 ② 处改，就必须让客户端先去 ②；而 ② 的主机名（Steam 版 = `d2vaidpni345rp.cloudfront.net`；日服 = `yostar-serverinfo.bluearchiveyostar.com`）是客户端里唯一的"种子"。**

### 4.3 日服 vs Steam：种子对比表（★ 对我们最有用的对照）

| 区域 | SDK 主机 | **serverinfo/state 主机（种子）** | 网关主机 | 游戏 API 主机 | 日志主机 | 来源 |
|---|---|---|---|---|---|---|

### 4.4 对我们的三个可执行假设（★ 这是本文最该被采纳的部分）

> 前提校正：报告 01 说「只剩运行时解密这一种可能」。但上游两个项目**从未尝试在二进制里找 serverinfo 主机**，而是：
> - BaPs：**直接把它当已知常量重写掉**（`yostar-serverinfo.bluearchiveyostar.com`）；
> - Shittim：**按端口 5100 兜底**，不管域名。
>
> 也就是说，**"必须静态定位 state-api"这个前提，上游没人验证过，也没人需要它。**

**假设 A（最高优先级）：serverinfo 主机由 SDK 的 `/common/config` 响应下发。**
依据：
- 我们已实测改 `sdk_url` 后，**第一个请求就是 `/common/config`**（报告 01 行 56）。
- AiriSDK 的 `OfficialPluginImpl` 负责 `loadPlugin(channelName=official)`，插件配置是 SDK 层的东西，**不是 il2cpp 业务层**。
- 日服的 `yostar-serverinfo` 与 `ba-jp-sdk` 是两个独立域名，但 BaPs 只重写了这两个 + 网关 + 游戏 → 说明 SDK 侧很可能自己知道 serverinfo 从哪来（配置或首次响应）。
- **验证方法（成本极低）**：拿真实的 `/common/config` 响应体，逐字段 diff，看有没有 URL / 域名 / `server` / `state` / `region` 字段。**我们已经有 sdk_url 打通的通道，这是最近的一条路。**

**假设 B：serverinfo 主机由 SDK 登录响应（`/user/quick-login` 或 `/user/detail`）下发。**
依据：同 A 的请求链；AiriSDK 登录成功后返回 region/server 列表是常见设计。

**假设 C：按端口兜底，绕开主机名问题。**
依据：Shittim 原文「Redirect any connection on **port 5100** to our local gateway, **regardless of the destination host**」。
**做法**：如果国服网关端口固定（如 443/其他固定端口 + 固定路径 `/api/gateway`），我们可以在**代理层按「端口 + 路径」拦截**，根本不需要知道域名。
**额外**：`r/Dk.xml` 已确认 `cleartextTrafficPermitted=true`（全域名允许明文），所以**明文拦截可行**，不必攻 TLS。

**假设 D（兜底）：在 `libunity.so` 的 `getaddrinfo` 做 code cave。**
这是我们报告 01 行 298 已列的方案。**上游没人这么做**（他们不需要）。风险：`libunity` 受 ACE 校验（报告 01 已验证 4 字节补丁即 SIGBUS）。**优先级应低于 A/B/C。**

### 6.2 数美 / ACE / Themis 绕过：有一篇高质量中文实操（★ 强烈建议 Lead 精读）

来源：看雪论坛 [【原创】某环逆向 TOP3：反作弊与反调试](https://bbs.kanxue.com/thread-293060.htm)，**2026-09-26 17:47**，作者附 GitHub 工程 [Machao147258-max/yh-top3](https://github.com/Machao147258-max/yh-top3)【原文】

> 注：这篇讲的是另一款游戏（完美/腾讯系 UE5 手游），**不是 BA**。但反作弊组件**高度重合**（`libtprt.so` = ACE、`libthemis.so`、`libturingmfa.so` = 图灵盾、`libsecsdk.so` = 网易易盾），方法论可直接迁移。

**原文的核心方法论（这是精华，逐条）**

> **§五 怎么堵：看路，不看点**
> 一条经验：看它读环境走哪条路，就往那条路堵。
>
> | 它走哪 | 在哪堵 |
> |---|---|
> | Java API | 改返回值 |
> | libc / `syscall()` | hook libc |
> | 内联 `svc` | patch svc |
> | **自带 syscall 引擎** | **hook 该引擎** |
>
> 另一条是**堵漏斗，不堵点**。ACE 的汇总通道：
> `libtprt 检测 ──(ioctl/gp*ioctl)──> Java AceManager ──> h.trace.qq.com`
> 堵 `libtprt.so` 的 ioctl，或在 Java 层把 `AceApplication.initialize` 改返回 0。

**⭐ 这一条直接命中我们的架构**（报告 01 的行 33-36：我们已知 `:GP6Service/:GP7Service` + `gp6ioctl/gp7ioctl` + `AceApplication.attachBaseContext`）。
**⇒ "堵漏斗不堵点" = 不要逐个绕检测点，去堵 `gp6ioctl/gp7ioctl` 这个汇总通道，或让 `AceApplication.initialize` 返回 0。这是我们当前最省力的方向之一。**

**其它可直接抄的原文结论：**

| 结论 | 原文 |
|---|---|
| ACE 字符串不明文 | 「`libtprt.so` 里有个分发器 `sub_111740(int a1) → return off_163750[a1 % 100]()`，用 unidbg 的 `Module.callFunction` 枚举 id 0..2000，dump 出 **101 条明文**」 |
| ACE 不走 libc | 「文件检测不调 libc 的 `open/stat`，走 `tp_syscall_imp`（`0x146be0`），用内联 svc 进内核。**所以 libc 上挂 open hook 抓不到它**」 |
| ACE 自退点 | 「`stop` 跟 `enable_gp7_exit_group` 一起走到，进程就 `exit_group` 退出——unidbg 里看到 `libtprt.so` 在 **`0x2603c`** 跑了条内联 `svc #0`。把这处 patch 掉就能拦住」 |
| ACE 检测清单 | 调试器(`TracerPid`)、进程名、内存映射、fd、模拟器(`/init.vbox86.rc`、`/dev/socket/genyd`)、ADB/USB、注入痕迹(`/data/data/com.tencent.tinput`)、自身完整性(`assets/__tpinfo.tsc`、`__acinfo.tsc`)、开关(`DetailSecurityCheck`、`__acignore.acc`) |

## 7. 对我们「硬啃那一步」的正面回答

我们卡点原文（报告 01 行 17）：

> **「客户端第一次连接网关前，那个主机名是从哪来的」**——静态三边 + 表包 + 两个落盘配置全部排除，只剩「运行时解密」这一种可能。

**上游给出的三条反证：**

1. **Shittim 从不"找"网关地址**——它按 **端口 5100** 兜底重写，注释原文：`regardless of the destination host`。**地址未知不影响接通。**
2. **BaPs 从不"找"serverinfo 主机**——它把 `yostar-serverinfo.bluearchiveyostar.com` 当**常量**写死重写。**这个域名在日服客户端里是否明文存在，BaPs 作者根本不需要知道。**
3. **两家都确认 gateway URL 是服务端下发的字段**（`ConnectionGroupsJson` / `Queuing_GetTicket`），**不是客户端常量**。

**⇒ 因此「只剩运行时解密」这个结论，很可能是因为把问题建模成了「必须静态定位一个字符串」；而上游把它建模成「必须在第一跳之前建立可控的拦截层」。**

**建议的验证顺序（成本从低到高）：**

| 序 | 动作 | 依据 | 成本 |
|---|---|---|---|
| 1 | **逐字段 diff 真实 `/common/config` 响应体**，找 URL/domain/region/server 字段 | 假设 A；我们已有 sdk_url 通道 | 极低 |
| 2 | 同样 diff `/user/quick-login`、`/user/detail` 响应 | 假设 B | 极低 |
| 3 | 检查 AiriSDK 插件目录/资产（`OfficialPluginImpl` 相关）里是否有 serverinfo 配置 | 假设 A 的静态版 | 低 |
| 4 | **按端口+路径兜底拦截**（`/api/gateway`、固定端口），完全不依赖域名 | 假设 C；Shittim 原文 | 低 |
| 5 | 利用 `cleartextTrafficPermitted=true`，**明文直连**而非 MITM | 报告 01 行 54 | 低 |
| 6 | `libunity` `getaddrinfo` code cave | 假设 D；上游无人做，且受 ACE 校验 | 高 |

**另附一条结构性检查单（来自 Shittim 文档，我们可能还没做）：**
> region 相关的**三个字符串必须完全一致**：① `global-metadata.dat` 里的枚举成员名 ② 独立的 region 字面量 ③ **服务端下发的 connection group 名**。
> 三者不一致 ⇒ `Queuing_GetTicket` 返回**空 gateway URL** ⇒ 卡加载界面。

**⇒ 如果我们哪天"地址对了但还是连不上"，请优先查这三者是否拼写一致。** 这可能表现为「认证服务器拒绝了请求」之外的另一种症状（空地址 → 卡 loading），值得作为排查项记录。

## 11. 给 Lead 的三句话

1. **我们不需要在 `libil2cpp` 里找到 `state-api`。** 上游两个私服都没做这件事，也都跑通了；Shittim 甚至用「按端口 5100 兜底，不管域名」直接绕过。
2. **最便宜的下一步是 diff 真实 `/common/config` 响应**——我们已经有可用的 `sdk_url` 通道，而这是 SDK 层最可能携带 serverinfo 地址的地方；成本近乎为零。
3. **国服是真空，但技术可行已被国内改包生态反证**；同时 `res/Dk.xml` 的 `cleartextTrafficPermitted=true` 让我们免于攻 TLS，这是日服/Steam 都没有的优势，应该优先利用。
