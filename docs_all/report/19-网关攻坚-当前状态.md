## 2. ★ SNI 根因（今晚最重要的发现）

客户端建 TLS **不发 SNI** → 一直落在 nginx 的 `0.default` 块 → 拿到 `CN=default` 自签证书。

| 对照 | ServerFlight |
|---|---|
| 带 `-servername gsqc-api` | **2601 B** |
| 不带 SNI | **1355 B** |
| 手机实测 | **1352 B** |

修法一行：`listen 443 ssl default_server;`（`ba_mitm.conf:2`，备份 `ba_mitm.conf.bak.1794590779`）。
改后无 SNI 时 ServerFlight = **2597 B**，三条自验通过（无 SNI 拿我们的证书 / 带 SNI 不变 / `example.com` 真证书未被误伤）。

**方法论教训**（已写进 `06-手机基线恢复.md §7.7`）：
1. 之前所有 TLS 结论（含 `access_denied` 定性）都是在"客户端落默认块"前提下得出的，**全部需要重估**；
2. 正确顺序：**先比对 ClientHello 有无 SNI + ServerFlight 字节数与对照是否一致**，再谈证书内容；
3. `error.log` 为空 ≠ 握手成功（alert 后正常 FIN，nginx 不记）。
