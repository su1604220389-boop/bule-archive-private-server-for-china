### 5.2 已排除的解释（逐条 + 为什么）

| # | 假设 | 判定 | 为什么（证据） |
|---|---|---|---|
| 1 | **缺推送通道**（客户端在等 WebSocket/SSE/长轮询） | **排除** | Shittim 全源码**零**推送：`WebSocket` / `SignalR` / `text/event-stream` / `EventSource` / `FlushAsync` 全量 grep **0 命中**；管道里没有 `UseWebSockets`/`MapHub`；三个 action 全是一次性返回。而 Shittim 在**完全没有推送**的情况下能带客户端进大厅正常游玩（`report\75` §3，三道独立证据） |
| 2 | **Content-Length / chunked / gzip** 没处理好，包没被消费完 | **排除** | 客户端 **20.000 s 空闲计时器正常起跳**（5/5 次样本一致：末响应后精确闲置 20 s 才拆连）⇒ 该连接被判定为 **idle 而非忙/脏**，说明响应被**完整消费**、无残留半包。另 `report\41` 已实测 chunked/gzip 均正常（`report\75` §4.0） |
| 3 | **证书 / 信封 / 协议号格式** 不对 | **排除** | 前三关全过：`Account_Auth`(1002) 让我们进昵称页、`Nickname`(1001) 进发音页、`Academy_GetInfo`(24000) 的请求与响应都被接受（20 s idle 证明）⇒ TLS 终结、AES 信封、内层整数 `Protocol`、`Hash>>32` 协议号判定**全部成立** |
| 4 | **SessionKey 缺失**（客户端在等会话凭据） | **已实测否证** | P0-0 已下发对象型 `SessionKey{AccountServerId:1, MxToken:<uuid4>}`（响应 1088→**2648 B / 32 内层键**）+ `StaticOpenConditions` 55 键字典 + `ServerTimeTicks` 非 0，**客户端下一轮请求里 `SessionKey` 仍是 `null`、`AccountId` 仍是 `0`** ⇒ 补 SessionKey 这条路**未能改变客户端任何行为**（A19.3 / A19.6） |
| 5 | **死 socket 复用**（第 4 条请求写进了已被拆掉的 keep-alive 连接） | **时间上不成立** | 若第 4 条请求在 `06:06:44` 创建（= 弹窗 `06:07:44` − 60 s），那时连接 **还活着**（`06:07:01` 才拆）⇒ "写进死管道"缺前提。另 20 s 更像客户端 BestHTTP `MaxConnectionIdleTime` 出厂默认，我方栈内**无任何 20 s 计时器**（stream 600 s / http 60 s / bridge 无 timeout）（`report\75` §4.0） |

**已排除的旁支**（不必再花时间）：`report\84` §5 已排除"证书链缺 intermediate / CA 库被破坏 / 版本号导致 404 / TLS 协商失败"；`report\74` §2.6 已排除 4xx/5xx 与异常路径（`api_probe.out` **0 字节**，全空）。

### 5.3 剩下的唯一可能

- **客户端拿到 24000 的 620 B 响应后，在内部"落地处理"这一步失败了**，且失败发生在**它自己发起下一条请求之前**（因为 wire 上一个字节都没有）。
- 具体是哪一处【推断，未证实】：
  - `AcademyDB` 反序列化成功但业务校验/资源定位失败（如 `ZoneScheduleGroupRecords` 空字典触发的空引用）；
  - 24000 之后的**下一条请求被客户端请求准入/回调链挡在池外**，等满 `RequestTimeout=60 s` 才炸（这与"零字节到达"唯一自洽的解释）；
  - 或客户端把 `gsqc-api` 重新解析到了别处（`report\74` §4 列为**唯一无法用服务器日志排除**的替代解释）。
- **静态分析已到尽头**：`HttpGameSession` 与各 handler 本体落在 **ACE 编码页**（`HandleAccountAuthResponseMessage` 等 7 个方法首 16 字节非 ARM64，A-5），明文只有 `AccountAuthStart` / `IsLoginFinished` / `co_RelayPacketsProcess` 等 4 个入口壳。
- ⇒ **下一刀必须走运行时观测**，服务端再盲改收益已极低（`report\83` §7 同样结论）。

### 5.4 这一节不该再被误判的三件事

1. **不要用文件体积判断弹窗**（标题页 2.9–4.0 MB 与弹窗 1.4–2.3 MB 有重叠）→ 用像素判据 `_tmp/chkcard.py`（`report\84` §0）。

3. **不要把 `127.0.0.1` 来源的 gsqc 会话当成客户端**（`----TENTEST` / 无 `REQUEST-ID` / `ae="-"` = 手工 curl，`report\74` §2.5）。

| # | 边界 | 含义 |
