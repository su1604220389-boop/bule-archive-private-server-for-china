## 三、网关协议已摸清（重要资产）

`Shittim-Server` 的 `/api/gateway`：

```
POST + application/json                  → 500  This request does not have a Content-Type header
POST + application/x-www-form-urlencoded → 400  "Expecting an mx file"
GET  /api/gateway                        → 200  空 body
```

⇒ **`/api/gateway` 吃 `multipart/form-data`，里面带一个 FlatBuffers 的 `.mx` 文件。** 与源码里 `GatewayController.GatewayRequest()` 调 `ReadForm()` 吻合。

### 认证链路（源码实测）
```
Protocol.Queuing_GetAuthTicket   请求 {YostarUID, YostarToken}
   → AuthTicket = base64("YostarUID/YostarToken") + RSA 封的 AES key
Protocol.Account_CheckYostar      请求 {UID, EnterTicket(=AuthTicket), ...}
   → {ResultState=1, SessionKey, ...}
```

服务端处理（`AccountHandler.CheckYostar` 原文）：
```csharp
var parts = Encoding.UTF8.GetString(Convert.FromBase64String(request.EnterTicket)).Split('/');
publisherId = long.Parse(parts[0]);
token       = parts[1];
// 完全不验签、不回调 TapTap，直接按 publisherId 查/建账号
response.ResultState = 1;
```

**三条硬约束**：`uid` 必须纯数字且 ≤ long；**`token` 绝不能含 `/`**；`ResultState` 必须回 `1`。
我们当前的值：`uid = 314816420`、`token = 61de1d1b7519ab1231866f74c11fcfdd1f80b210`（40 位 hex）——**三条全部满足**。

## 四、判据纪律（今晚用血换来的五条）

1. **`mark=262253` 只证明「手机侧 iptables 规则匹配了、conntrack 建了条目」，不证明「包真发到了我们网卡」。** 判断连接有没有到我们，**只认 pcap 里有没有包**。
2. **`tcp-access.log` 是会话结束时才落盘**，用它否定一条仍 ESTAB 的长连接是无效的。
3. **`tcp-access.log` 记的是「上游」**，被我们接管的连接上游恒为 `127.0.0.1:8443`，用 `grep 目标IP` 去查它恒为 0，对「是否被劫持」无区分力。
4. **阿里 SLB 上多个域名共用同一组 IP**（`gsqc-api` 与 `udata-api.open.yostar.net` 共享 `112.13.210.86 / 39.173.157.74 / 39.174.179.5`）。`ss` 只给 IP、不给域名，**凭 IP 反推域名必然出错**。认域名只能看 DNS 解析记录或 SNI。
5. **判 TLS / 判连接，都要先问「这个观测在什么时机写入、覆盖什么状态」** —— 上面 1~3 是同一个毛病的三个变体。
