## §1 ID 表结构与解析结果

### 1.1 文件事实（实测）

| 项 | 值 |
|---|---|
| 字节数 | 249,143 |
| 编码 | **UTF-8，无 BOM**（严格模式解码通过，未做 GBK 回退） |
| 行尾 | **纯 LF**（`\r\n` 计数 = 0），末行带 `\n` |
| 行数 | 7,937 |
| 字符数 | 142,597 |
| 段标题 | 11 个，全部由 `=` 包裹 |

标题写法**不统一**，不能按固定模板匹配：

```
========== 学生 ==========
========== 剧情==========              ← 收尾的 = 前没有空格
========== 关卡  ==========            ← 有两个空格
========== 精英/首领级敌人 (704) ==========
```

解析器用 `^\s*=+\s*(.+?)\s*=+\s*$` 抓标题文本，再按前缀匹配段名，把 `(704)` 这类计数后缀丢掉。

### 1.2 行结构

```
<ASCII 数字 ID><1~2 个空白><名称>
```

- **ID 宽度 1~9 位**，不定宽。分布：

| 位数 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|
| 条数 | 28 | 59 | 80 | 430 | 1481 | 605 | 3701 | 25 | 1427 |

  > 任务书说"至少有一处是 `3 高级强化珠`"。实测 **1 位 ID 共有 28 条**，分布在 4 个段：
  > 道具段（1,2,3,7,8,9）、**装备段（1,2,3,4 —— `3 高级强化珠` 在第 5281 行，你的例子在这里）**、
  > 货币段（1~9）、家具段（1~9）。最长 9 位（如 `560120001`）。
- 名称里**可以含空格**：`回转 FX Mk.0`、`D.U. - 山海经并行普通线`。所以不能按空格切字段，只能"吃第一个数字串 + 一段空白，剩下全是名称"。
- 名称里**可以以数字开头**：`1次招募券`、`10次招募券`、`1号店招待券`、`227号温泉乡向导图`、`56号商业区旧址`。用贪心 `^(\d+)\s+(.+)$` 才不会把它们切错。

### 1.4 关键发现：`（…）` 行不是注释，是**折行续行**

这条要写进 Lead 的读法里 —— **当成注释跳过就丢字**。

任务书假设那些"只有括号没有 ID"的行（`（百鬼夜行）`、`（阿里乌斯）`…）是注释。实测它们是**上一条名称折行后的第二行**，共 80 条，必须粘回去。

**证据一（同一份数据存在两种排法）**：道具段 3090~3093 **没有折行**，写成

```
3091  中级战术教育BD（海兰德）
```

而 3000~3083 折行写成

```
3000  初级战术教育光盘
（百鬼夜行）
```

两种排法指向同一类东西，说明括号是**名称的一部分**（`初级战术教育光盘（百鬼夜行）`），不是注记。

**证据二（货币段可交叉验证）**：货币第 9 条折行成

```
9  悬赏通缉
（街区战）挑战券
```

而同段第 22 条是**另一种**未折行写法 `悬赏通缉挑战券`。所以第 9 条的全名只能是 `悬赏通缉（街区战）挑战券`，`（街区战）` 是限定语、`挑战券` 是后缀，整段都得粘。

**证据三（礼物副标题）**：只有 2 条续行是 `~…~` 形态，语义上不是名称的一部分，单独存：

```
5003 无法实现的爱恋  +  ~正因为是不被世间容许的爱，才更令人流连忘返~
5015 跳跃侦探兔    +  ~由大雾引发的温泉滑倒事件~
```

续行分三类，处理方式不同：

| 形态 | 条数 | 例子 | 处理 |
|---|---|---|---|
| 纯括号 `（X）` | **72** | `（百鬼夜行）` | 直接粘到名称末尾，并单列 `school: "百鬼夜行"` |
| 括号+尾巴 `（X）Y` | **6** | `（街区战）挑战券` | 整体粘到名称末尾 |
| `~说明~` | **2** | `~正因为是不被…~` | 名称不变，另存 `subtitle` |

> 粘接**不加分隔符**（中文无词间空格），这与未折行写法 `中级战术教育BD（海兰德）` 完全一致；已由自检 B 逐字符证明。

### 1.5 跳过的行

**只跳过 10 行，全部是段与段之间的空行**，原因分布 `{"blank": 10}`，`otherSkipped: 0`。

也就是说：**没有任何一行因为"看不懂"被丢弃**。任务书担心的"只有括号没有 ID 的注释行"，0 条被丢弃 —— 80 条全部识别为续行并正确归属。

### 1.6 行数守恒

```
7,937 = 11(段标题) + 10(空行) + 80(续行) + 7,836(数据行)
```

`_meta.lineAccounting.balanced = true`。所以 `7836 + 10 ≠ 7937` 不是丢行，差额就是那 80 条续行 —— 已在 `_meta` 里显式记账。

### 1.7 无损自检（`verify_ids.py`，退出码 0）

三道检查，三个角度互相独立：

- **A. 逐行精确比对** —— 重新逐行走一遍原表：每条数据行的 ID 和名称必须与 `ids.json` 对应条目**逐字符相等**；每条续行必须正好被完整粘进上一条。12 段 **mismatch 全为 0**。
- **B. 聚合无损比对** —— 每段原始行去掉所有空白后拼接，必须等于解析结果去空白后拼接。**12 段长度与内容全等**。
- **C. 守恒与结构** —— 行数守恒、ID 全为 `int`、名称非空、段内重复 ID 与 `_meta` 申报一致、`sectionCounts`/`totalLines` 与实测一致。

```
结果: PASS —— 12 段 7836 条全部逐字符对上原表，一个字都没丢
```

### 1.8 重复：段内 0，跨段大量 —— 所以绝不能按名字去重

**段内重复 ID：全表 0 条**（`_meta.duplicateIds = {}`）。任务书要求"同一分段内重复 ID 要报告出来"，结论是**没有**，不是静默去重了。

**跨段重复则非常多**，这正是不能去重的原因：

| 指标 | 数值 |
|---|---|
| 全表唯一 ID | 5,343 |
| 出现在 >1 段的 ID | **1,804**（2 段:1399 ／ 3 段:121 ／ 4 段:284） |
| 不同名称总数 | 3,494 |
| 出现在 >1 段的名称 | **345** |

典型例子 —— ID `7300100` 在三个段各出现一次，名称还不同：

| 段 | 行号 | 名称 |
|---|---|---|
| 剧情 | 291 | `比纳` |
| 敌人 | 1154 | `比纳` |
| 精英/首领级敌人 | 3555 | `比纳` |
| 总力战/大决战 Boss | 6867 | `比纳（比纳）` |

> `比纳（比纳）` 是**原表就长这样**（已回查第 6867 行原文），不是解析 bug。
> 货币段 2/3/4 号更是三条同名 `青辉石`。这些都必须原样保留。

### 1.9 附带发现：关卡 ID 是可解码的结构化 ID

`stages` 段 250 条**全部是 7 位**，格式 `1 | AA | BB | CC`：

| 位 | 含义 | 取值 |
|---|---|---|
| `1` | 固定前缀（Campaign） | 恒为 `1` |
| `AA` | 区域 / 章节 | `01` ~ `30`，共 **30 个区域** |
| `BB` | 关卡块类型 | `11`(150 条) / `14`(10 条) / `21`(90 条) |
| `CC` | 块内序号 | `01` 起 |

例：`1011101` → 区域 01 / 块 11 / 序号 01（`青叶中心区35号街`）；`1302103` → 区域 30 / 块 21 / 序号 03（`教堂广场 4号街`）。

各区域关卡数只有 8 或 9 两种，合计 `150 + 10 + 90 = 250`，与总数吻合 —— 说明这套解码是自洽的，**不是猜的**。Lead 要按章节放行关卡时可以直接按 `AA` 分组，不用额外映射表。

## §2 `ids.json` 的 schema 与 `_meta`

### 2.1 顶层结构

键顺序 = 表内出现顺序，便于人工比对：

```json
{
  "special":       [{"id": 19900000, "name": "阿罗娜"}, ...],
  "students":      [{"id": 10000, "name": "爱露"}, ...],
  "story":         [...],
  "enemies":       [...],
  "eliteBoss":     [...],
  "items":         [{"id": 80062, "name": "胡子洗发水"}, ...],
  "equipment":     [{"id": 3, "name": "高级强化珠"}, ...],
  "currencies":    [{"id": 3, "name": "青辉石"}, ...],
  "furniture":     [...],
  "stages":        [{"id": 1011101, "name": "青叶中心区35号街"}, ...],
  "raidBoss":      [...],
  "grandAssault":  [...],
  "_meta":         {...}
}
```

### 2.2 单条记录

| 字段 | 类型 | 必有 | 说明 |
|---|---|---|---|
| `id` | `int` | ✔ | 已 `int()` 转换，**不是字符串**。最大 704,241,205，远小于 int32 上限 |
| `name` | `str` | ✔ | 原表名称，折行已粘回完整形态 |
| `school` | `str` | ✘ | 仅当续行是纯 `（学校名）` 时出现，72 条 |
| `subtitle` | `str` | ✘ | 仅当续行是 `~…~` 时出现，2 条（已去掉两侧 `~`） |

例：

```json
{"id": 3000, "name": "初级战术教育光盘（百鬼夜行）", "school": "百鬼夜行"}
{"id": 5003, "name": "无法实现的爱恋", "subtitle": "正因为是不被世间容许的爱，才更令人流连忘返"}
{"id": 9,    "name": "悬赏通缉（街区战）挑战券"}
{"id": 22,   "name": "悬赏通缉挑战券"}
```

> `school` 是**附加**视图，`name` 里已经含了括号全文。想按学校筛选用 `school`，想要完整显示名用 `name`，两份信息不重复计算。

### 2.3 `_meta` 字段表

| 键 | 内容 |
|---|---|
| `source` / `encoding` | `全ID.txt` / `utf-8` |
| `totalLines` / `totalChars` | 7937 / 142597 |
| `parsedEntries` / `skippedLines` | 7836 / 10 |
| `sectionCounts` | 每段条目数（12 项） |
| `sectionLines` | 每段标题所在行号 |
| **`lineAccounting`** | `{totalLines:7937, sectionHeaders:11, blankLines:10, absorbedContinuationLines:80, dataLines:7836, otherSkipped:0, balanced:true}` |
| `duplicateIds` | `{}`（段内无重复） |
| `skippedReasons` | `{"blank": 10}` |
| `skippedLines_detail` | 10 条跳过的行号 + 原文（空行） |
| **`continuationLines`** | `{total:80, byKind:{cont_school:72, cont_paren_tail:6, cont_subtitle:2}, detail:[{line,text,kind,attachedTo,section}...]}` |
| `idRangeBySection` | 每段 `[min, max]` |
| `parseRules` | 行结构、ID 宽度、去重策略、续行策略的机器可读说明 |

`continuationLines.detail` 把 80 条续行的**行号、原文、归属条目 ID** 全部留档，任何人都能逐条复核粘接是否正确。

### 3.4 初始角色：白子（UniqueId `10010`）

从 278 个学生里挑 `10010 白子`，四条依据：

1. **是无后缀的基础形态。** `students` 段里同一角色的换装是**独立条目带后缀**（`10024 白子（骑行）`、`20027 白子（泳装）`、`10100 白子＊恐怖`）。初始单位只能用基础形态，否则客户端按换装 ID 去查基础数据会错位。

3. **落在首发批次。** ID `10010` 在最早的 `10000–10099` 基础批次内（该批次共 100 个角色），说明资源/技能表最全，最不容易因为缺数据而白屏。

### 3.6 可复现性

- 时间恒定；`ServerId` 由确定性分配器从 `--server-id-base`（默认 `1000000`）顺序发号，账户 `1000000`、角色 `1000001`。
