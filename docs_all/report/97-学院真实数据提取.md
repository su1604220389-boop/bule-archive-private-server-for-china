## §1 为什么做这个

卡点现状（沿用今天已确认的事实）：客户端走完 `Academy_GetInfo(24000)` 后不再发请求，60 秒报「同步账号信息时发生错误」。
今天四次"形状"假设（`SessionKey` / `AccountDB` / `ServerTimeTicks` / `StaticOpenConditions`）都被实验否掉。

我们当前发给客户端的学院部分是这样：

```json
{"AcademyDB": {"LastUpdate": "2026-11-14T00:00:00",
               "ZoneVisitCharacterDBs": [],
               "ZoneScheduleGroupRecords": {}},
 "AcademyLocationDBs": []}
```

也就是说：**"这台账号一个学院地点都没有"**。而客户端自己的 `ExcelDB.db` 里明明有 11 个地点、12 级学院等级、1053 条日程。
一个已经被 `Account_Auth` 建档的账号，`AcademyLocationDBs == []` 在真服上**几乎不可能出现**（新号也至少有 Schale Office）。

⇒ 本轮的假设是：**空学院数据 = 客户端拿不到任何可建的地点节点，学院 UI/缓存初始化在等一个非空的 `AcademyLocationDBs`，等不到就静默卡住，60 秒后由超时兜底报错。**
本轮只做一件事：**把"非空"要用到的真实数据从客户端数据表里挖出来**，让假设能被实验验证（而不是再猜第五个形状）。

## §3 FlatBuffers 解码方法与结果

### §3.1 实测布局（`AcademyLocationDBSchema` Id=1，184 B）

```
0000: 1c000000 00001600 38002c00  | root=0x1C(28)  | vt@6: vt_size=22, tbl_size=56
0016: 28002400 20001c00 18001400  | field offsets: 44,40,36,32,28,24,20,12,4
0024: 0c000400 16000000            | tbl@28: soffset=22 -> vtable=28-22=6
0032: 01000000 00000000 60ea0000  | f8=1        f7=60000
0048: 04000000 20000000 28000000  | f6=4  f5->84  f4->96
0064: 54000000 041d0071 01000000  | f2->148(预制体)  f1=0x71001D04  f0=Id=1
0080: 00000000 01000000 00000000  |  ...
0096: 01000000 00000000 26000000  |  ...
0112: 55304973... "UIs/00_Images/BigBtn/Location_Image_01"（string hdr 在 104, len=38）
0144: ... 1d000000 "Academy/Location_SchaleOffice"（string hdr 在 148, len=29）
```

要点：**vtable 在 table 前面**（`table_pos - soffset`），字段 offset 为 0 = 该字段缺省（Id=7/17/19 三行就各缺两个字段，`tbl_size` 从 56 掉到 44/48）。

### §3.2 反射算法（无 `.fbs`）

1. `root = u32(buf,0)` → root table。
2. `soffset = i32(table)` → `vtable = table - soffset`；校验 `vt_size%2==0`、`4<=vt_size<=512`、`tbl_size`、每个非零 field offset `< tbl_size`、vtable 不压进 table。
3. 每个字段位置 `p = table + offset`：
   - 若 `v = u32(p)`，`p+v` 在同一 buffer 且 4 对齐，依次试 **table / string / vector**；
   - 都不过 → 按 `int32`。
4. **整表逐字段投票**定型（同一字段在 11/12/1053 行里必须是同一类型），避免单行假阳性。
5. 三条防假阳性规则（踩过坑，记下来）：
   - string 必须 **NUL 结尾 + 全可打印**；`len<=1` 的"字符串"一律让位给 vector（单个可打印字节最容易假阳性）；
   - vector 的元素区间**不许压到任何已识别的 string**（否则就是 `f6=4` 那种"指向 32 元素数组"的假 vector）；
   - 与 SQL 主键逐行相等的字段（`f0 == Id`）**强制按 int**，不参与 uoffset 猜测。

> 同目录已有 `work\ba\data\fbparse.py`（单行无投票的启发式读取器）与 `fb_dump.py`。本轮**没有复用它**，而是重写了一份带「整表逐字段投票 + 假阳性抑制 + SQL 主键互证」的 `dump_academy.py`：
> `fbparse.py` 单行判定没有投票，实测会把 `f6=4` 判成"32 元素 vector"、把 `f0=Id` 判成 vector（见上表和 §3.3 的坑），无法直接支撑这次的产出。两者的解析内核（vtable 读取）是同一套。

## §6 卡在哪 / 下一步怎么办

### §6.1 两个"值对不上"的风险点（必须先说清楚）

1. **`ZoneScheduleGroupRecords` 的语义**。DTO 只说是 `Dictionary<long,List<long>>`，没说 value 是"该组全部日程"还是"该组**已完成**的日程"。
   名字带 `Records`，很可能是**玩家进度**——那新号应该是 `{}` 或者每组空列表。
   ⇒ 本 JSON 同时给了 `ZoneScheduleGroupRecords_keys`（254 个 key）和 `ZoneScheduleGroupRecords`（key → 全部 Id）。
   **建议实验顺序：先只换 `AcademyLocationDBs`（records 保持 `{}`）；如果还卡，再把 records 用"key → 空列表"发一次；最后才用"key → 全部 Id"。**
   直接把 1053 条当"已完成"发出去，最坏情况是把所有 momotalk 标记成已读。
2. **`Rank=1 / Exp=0` 是初始态，不是解出来的行值**。如果客户端会拿 `AcademyLocationRankDBSchema` 校验（例如"Rank=1 必须 Exp≥0 且 <100"），那就是自洽的；如果它要求新号 Rank=0，需要再试一档。

### §6.2 三条可立刻做的 A/B（每条只改一个变量）

| 实验 | 改动 | 预期 |
|---|---|---|
| **E1** | `AcademyLocationDBs` = 11 条真实地点，其余不动 | 若卡点消失 ⇒ 结论"空地点数组导致停摆"成立，收工 |
| **E2** | E1 + `ZoneScheduleGroupRecords` = `{10000:[],10001:[],…}`（254 个 key，空列表） | 若 E1 没好、E2 好 ⇒ 客户端还要"组节点存在" |
| **E3** | E1/E2 + 地点 20 补进去（12 条） | 若前两条都失败而这条好 ⇒ 客户端按 Zone 表反查地点，缺 20 触发断言 |

### §6.3 如果还卡，下一轮往哪挖

- **`ZoneVisitCharacterDBs`**：DTO 里 `kind=unknown`。但 `AcademyZoneDBSchema`（95 行）的 `f1` 已经证明能给出 zone ↔ location 映射，`AcademyZoneDBSchema` 还能解出 zone 的坐标/尺寸（`f4`/`f6` 是长度 3 的向量，像 `[10000, 0, 7500]` 和 `[47, 50, 1]`）。下一轮可以先把 95 个 zone 全解出来，看 `ZoneVisitCharacterDBs` 是不是"每个 zone 一个拜访角色"。
- **字段名而不是字段值**：现在拿不到名字是因为没有 `.fbs`。最快的两条路：① IL2CPP dump 里 `MX.GameLogic.DBModel.AcademyLocationDB` 的字段声明顺序（`work\ba` 下有 dump，`report/70` 用过）；② `AcademyLocationDBSchema` 的 SQLite 建表语句如果带注释（本库没有）。
- **文本 id 验证**：`f7 ∈ {4000,4010,4020,4030,4040,4050,4070,60000,60004,60018}` 如果是文本 id，本地 `ExcelDB.db` 里应该有一张 `Localize*` 表能对上。**注意：本轮没有动 `ExcelDB.db` 以外的任何大二进制**，下一轮可以只在 `ExcelDB.db` 里查 `%Localize%`/`%Text%` 表。
