## 6. 旧的错误结论 & 它们的真因

| # | 旧结论（原话） | 出处 | **真因** | 结论现在的效力 |
|---|---|---|---|---|

## 7. 下一步决策树

### 7.1 主线：CA 装成功（用户证书 ≈55% / 系统 CA ≈35%，合计 ~90%）

```
[P1] 装用户证书 → force-stop 游戏 → 重开
  ├─ 证书错消失
  │    └→ 打通判定：见 §7.3 的 A 段
  │       A1 游戏能进大厅 ────────────────── 目标达成
  │       A2 出现新的业务接口报错 → 进业务层（此时才轮到 S6/S7 的连接组 URL 问题）
  └─ 仍报证书错
       └→ [P2] init+zygote 系统 CA 注入（或 MoveCertificate 模块）→ 重开
            ├─ 通 → 同上 A1
            └─ 仍不通 → 走 §7.2 备选
```

**判定标准（必须可观测，不许看"感觉"）：**

| 阶段 | 判定通过的硬指标 |
|---|---|
| 证书信任 | 服务器 access log 出现**来自手机 IP** 的 `GET /api/state`（不是 `/api/health` 那种探测） |
| 路由 | 该请求的 `Host` 头 = `state-api.bluearchive-cn.com`（DNAT 不改 SNI，所以能验到） |
| 业务层 | 出现 `POST /api/gateway`（或 `/api/{实体}/{动作}`）且**状态码不是 500** |
| 大厅 | 客户端不再回标题画面 |

### 7.2 备选（CA 彻底失败时，按优先级）

| 序 | 路线 | 实现成本 | 成功率 | 需改什么 | 为什么它还没被有效证伪 |
|---|---|---|---|---|---|
| ① | **客户端桩点改 state URL** → `http://example.com/api/`（**明文**） | 中（走已有 cave 路线：`libil2cpp` 代码洞 + `DT_INIT`，已证不触发 ACE） | 中高 | 1 个 so + 注入桩 | 这是**唯一不依赖信任链**的落点（`06:332` 原话：一次性解决明文/证书/DNS 三件事）；而 `libil2cpp` 可改已被多次证实（`01 §4.1`） |
| ② | 同上，但改的是 **URL 常量**（等长替换成我们持有真证书的域名） | 高 | 中 | so 字节 | 等长域名难求；且 `C15` 已证明我们**有** `*.bluearchive-cn.com` 的叶子（自签），真证书那条需要我们的域名 |
| ③ | **全局 HTTP 代理** `settings put global http_proxy` | 低 | 低 | 1 条设置 | Unity 2021.3 支持**手动代理**（`2019.3` 已修），但**只解决路由、不解决证书**（`12:299`）⇒ 单独不能成立 |
| ④ | **per-app VPN** | 中高（1–2 天写 TUN） | 低 | 1 个 app | 比 DNAT 干净，但**同样不解决证书**（`12:319-321`）⇒ 与 ③ 同性质 |
| ⑤ | 重打包 + 改 manifest `networkSecurityConfig` 把我们的 CA 设成 app 级 trust-anchor | 中 | **低** | 重签 APK | Unity 用自己的 TLS 栈，**大概率不理会** `networkSecurityConfig`（`12:387`）；且重签会改签名 |

> ⚠️ ① 与 ② 的共同前提：**必须先有 ① 或 ② 之前的路由**。而"路由"这件事本身现在已经不是瓶颈（`iptables -t nat` 可用、`DNAT rc=0`），真正的瓶颈是**证书**。所以凡是"只解决路由"的方案（③④）都不构成独立路径。

### 7.3 三条必须同时满足的前置（否则装什么都白搭）

1. **根 CA 直接签叶子**，不要中间 CA；握手时**同时下发 leaf + root** —— UnityTLS **不自动补中间证书**（`12:182`）。
2. 证书 SAN 必须含 `state-api.bluearchive-cn.com`（以及 `gsqc-api.bluearchive-cn.com`，如果也要劫）（`12:368`）。
3. **先确认 `targetSdkVersion`**：CT 只在 `targetSdk ≥ 37` 时咬人，我们 `targetSdk=33` ⇒ **CT 与我们无关**（`06:271`、`12:206-207`）。

## 8. 给下一轮接手的人的 10 条铁律

1. **永远不要用 `cat > dst` 覆盖 `.so`。** 必须 `cp` 到同目录 `.new` → `sha256sum` 校验 → `restorecon` → `mv -f`（同 inode 一次换完）。`>` 是 `O_TRUNC`，被中断就留 0 字节，而客户端 0.3 秒就会重启抢跑。（`06:299`、`07:17`、`08:212`）
2. **写 iptables 之前先 `iptables -S` 存档；禁用 `-F`。** 只 `-A`/`-I`，用完必须 `-D`，收尾验 `iptables -S OUTPUT | grep -c <你的标记>` = 0。当前基线是"零自定义规则"。（`06:75`、`06:225`、`06:262`）
3. **`files/Hosts` 每次启动都会被重写**（state 成功时），它**不是**持久控制点。想验证必须先让 state 失败，而且即便失败它也不回落。（`06:73`、`06:212`、`06:263`）
4. **`/apex/com.android.conscrypt/cacerts` 与 `/system/etc/security/cacerts` 是 tmpfs，重启即失效。** 先把原目录拷出来再挂 tmpfs —— 挂上之后原目录就读不到了。（`12:A.3`、`06:267-269`）
5. **`/system/etc/hosts` 对本 app 无效**：解析在 **netd(pid 1937) 的另一个 mount namespace**。要动就进它的 ns（`nsenter -t 1937 -m`），别在 shell 的 ns 里 bind-mount。（`06:198`、`06:303`）
6. **别盯 `ba_mitm.log` 找手机流量。** `sdkcard.py:78-81` 的 `fix()` 会把主机名改写成 `example.com`，请求只进 `example.com.log`。找错日志 = 得出"客户端没打进来"的错误结论。（`09:778-780`）
7. **500 ≠ 鉴权失败。** Shittim 的 `/api/gateway` 见到非 `multipart/form-data` 就抛 `InvalidOperationException`；字段名必须是 **`mx`**。（`09:449`、`08:201`）
8. **`UseCustomExcel=true` 会先删 316 MB 资源再崩**；生效配置是 `Config/Config.json`，**不是** `appsettings.json`。同理 `.NET` 起不来先查 `DOTNET_gcServer=0`（`runtimeconfig` 里写死 `System.GC.Server: true`），不是内存不够。（`08:202`、`09:90`、`09:380`）
9. **证书 deadline 2026-12-05。** `vhost/letsencrypt/` 那份 LE 证书 **2026-11-26 过期且从未部署**，别让它自动部署（换上会让 TLS 立刻失效）。`acme.sh --renew` 这条路不存在。（`09:855-864`）
10. **这台 PC 会随机 bugcheck（11 天 3 次，代码各不同）。** 长跑任务（子 agent、271 MB IO、多实例 python）必须假设随时被打断，**关键状态一律落盘**；手机侧状态同样要落盘，因为设备也可能被意外重启。（`08:166-186`）

> 附则（不算铁律但同样致命）：
> - **UnityTLS 不补中间证书** —— 根 CA 直接签叶子，握手同时下发 leaf + root。（`12:182`）
> - **服务器 5000 被安全组挡** —— 别设计"让客户端直连 5000"的方案。（`09:475`）
> - **`kit/state_kit_v1/…/ca.crt` 是另一张 CA**，别和 `fd8b2b01` 混用。（`06:293`）
