## 2. 五条必须先纠正的认知（不纠正会继续烧时间）

### 2.1 ★ offset 标错了一格，而且错的是「修正版」

| 值 | 你文档里的说法 | 实测（`.rela.plt` 符号表 + `unity_full.asm` PLT 注释 + 洞内机器码三重验证） |
|---|---|---|
| `libunity + 0x13d94d0` | README 说「这才是 getaddrinfo」 | **`gettimeofday`** |
| `libunity + 0x13d94d8` | README 说「这是 libc 的 basename，错的」 | **`getaddrinfo`** ← 正确的那个 |
| `libunity + 0x13d95d8` | connect | ✅ connect（这条是对的） |

**后果**：现役 `libil2cpp_patched.bin` = `patch_hit2.py` 的 `g20.o`，它把 `gettimeofday` 改写成了 `getaddrinfo` —— timeval 不填、时间基准被破坏。
**这极可能直接就是 E64「从被官方拒绝变成超时」的原因**：不是链路变了，是把游戏的时间函数拆了。

→ **一个常量的修正，可能就换回一整个消失的现象。这应该是今天第一件事。**

### 2.2 ★ libil2cpp 根本不调用 `connect` / `getaddrinfo`

全段 346 万条 `BL` 扫描：libil2cpp 对这两个 PLT 桩的调用点 = **0**（其它 65 个桩被调 116,000 次）。
所以「改 libil2cpp 的 PLT/GOT 全无效果」的真因**不是 `-fno-plt`**（§4.9 的归因错了），而是**这两条导入在 libil2cpp 里压根没有调用者**。

真正活着的是 **libunity**：`getaddrinfo` 1 个调用点（`0xb84014`）、`connect` 3 个（`0xc036f8/0xcb4720/0xcf50c8`）+ 1 处直接读 GOT（`0x454788`）。

→ **落点只有一个：libunity 的 GOT。别再动 libil2cpp 的 PLT。**

### 2.3 ★ 网关地址不是秘密，`/api/state` 的 `Servers` 就是答案

你自己的 `ba-pentest.md:155-160` 已经抓到了：

```json
GET https://state-api.bluearchive-cn.com/api/state
{"Servers":["https://gsqc-api.bluearchive-cn.com/api/","https://gs-api.bluearchive-cn.com/api/"],
 "State":1,"Msg":"服务器维护中，请耐心等待开服！"}
```

**客户端只信一个种子，之后所有服务器地址由这个响应决定。**
上游同样的机制：BaPs 日服由 `server_config` 回 `DefaultConnectionGroup` / `ConnectionGroupsJson`；Shittim 文档明写「region 三处拼写不一致 → `Queuing_GetTicket` 返回空 gateway URL」。

→ 你要撬的不是字符串，是**这一个 HTTP 响应**。
→ 而且：`res/Dk.xml` 已确认 `cleartextTrafficPermitted=true` —— **只要 `Servers` 里给 `http://`，后面全链路明文，TLS 只需要解决 state 那一个请求。这是国服相对日服/Steam 的独有优势。**

### 2.4 ★ `Hosts` 那次实验大概率是无效实验

| 官方条目长这样（api-probe.md:14） | 你写进去的 |
|---|---|
| `'https://gsqc-api.bluearchive-cn.com:443'`（带 scheme 的完整 URL） | 裸 `127.0.0.1:9443` |

两个独立的失效因子：
1. **格式**：没有 scheme 的裸 host:port 大概率解析不出条目；
2. **时序**：你是**联网状态下**测的 → 客户端先拉 state、用响应覆盖了 `Hosts`，你写的条目在被读之前就没了（"游戏把官方条目追加回去"正是这个动作的证据）。

缺的对照组只有一个：**断网（飞行模式）启动**。
而且你自己在 §4.4 记过「断网时在另一台手机上能进主程序」—— 那台机器没有污染史，说明**离线路径是存在的**。

→ **飞行模式 + 正确格式的 Hosts** 是一个 10 分钟、零风险、可能一步通关的实验。见 §3-A2。

### 2.5 ★ ACE 把 libil2cpp 的导入函数换成了自己的转发表

我静态核到：`libil2cpp.so` 的 `.dynsym` 里**导入**了 `g_tprt_ori_array`，而 `g_tprt_pfn_array` / `g_tprt_ori_array` 是 `libtprt.so` 的**导出符号**（`libtprt_orig.so` 实测，偏移 `0x1a4b48` / `0x1a3210`）。

含义：ACE 在加载期把 libil2cpp 的部分 PLT 改成了"进 libtprt 的 wrapper、再用 `ori_array` 里的原指针回调"的结构。

**这解释了两件事**：
- 为什么"改 libil2cpp 的 PLT 有时能拦到、参数有时是垃圾" —— 你改的是 ACE 的转发表附近，不是一段普通 PLT；
- 为什么 libunity 完全不受这层影响 —— **libunity 不导入 libtprt**，它是干净的。这就是"libunity GOT 可靠、libil2cpp PLT 不可靠"的结构性原因。

顺带：这两个导出符号是**可读的**，等于给你一张「ACE 到底 hook 了哪些函数」的现成表（`pfn_array` vs `ori_array` 逐项比对）。

## 3. 你还没试过的 14 条路

> 编号可直接回复，我可以把任意一条展开成可执行脚本。
> 成本口径：**S** ≈ 半小时内、**M** ≈ 半天到一天、**L** ≈ 周级。
> 成功率是我的判断，标注了依据。

### A 组 · 客户端重定向（把流量导到我们）

**A1 · `connect` GOT 改写（唯一"已验证可行"的落点）** — 成本 S，成功率 高
- 作用：把 libunity 的 3 个 connect 调用点 + 1 处直接读 GOT，全部改写到 `127.0.0.1:9443`。
- 为什么现在能做：落点已确认活着；槽位已三重验证；`adr` 取 0 的坑已有解（局部标签）。
- 关键修正：**先 `grep 'libunity.so' /proc/$PID/maps` 判定 GOT 页是 `rw-p` 还是 `r--p`**。`libunity` 的 `.got` 落在 `PT_GNU_RELRO [0x1390f48, 0x13dc000)` 内，静态应当是 `r--p` —— 与你 §4.11「rw-p 可直接 str」冲突。**若真是 r--p，现役 v20 的 `str` 会在 DT_INIT 里直接 SIGSEGV**。这条不判清就动手，等于再赌一次运气。

**A2 · 飞行模式 + 正确格式 `Hosts`** — 成本 **S（10 分钟）**，成功率 中，**风险 0**
- 作用：验证「state 拉不到时，客户端是否回落到 `Hosts` 缓存」。若成立，整条 APK 注入线全部作废，纯文件篡改即可。
- 做法：`Hosts` 写成完整 URL（先试 `https://127.0.0.1:9443`，再试 `http://127.0.0.1:8080`）+ 飞行模式 + 本地起服务看有没有连接进来。
- **这是性价比最高的一条，应该是今天第二个实验。**

**A3 · 系统 CA（root 可用，仅用于验证）** — 成本 S，成功率 中
- 你因为有「单 APK 零 root 交付」的约束否掉了它。**但验证阶段你有 KernelSU root，而交付是几个月后的事**。先把"通路能不能走"和"怎么零 root 交付"分开，不要用远期约束卡住当下验证。
- 做法：`/system/etc/security/cacerts` 放自签 CA（Android 14 还要处理 `/apex/com.android.conscrypt/cacerts`），再把 `res/xml/Dk.xml`/`http.xml` 的 `trust-anchors` 加 `<certificates src="user"/>`。
- 判定：客户端是否完成握手。**成功=Unity 走系统 CA（很多 Unity 版本确实走）；失败=它用内置 BoringSSL CA 包，转 A4。**
- 附带：这条一旦成功，mitmproxy 一挂，W4/W7/W6 的信息**一次性全拿到**（真实路径、body 形状、握手包）。

**A4 · `CustomCertificateHandler.ValidateCertificate` → `return true`** — 成本 M，成功率 高（但依赖一个前置）
- 证据：`metadata-strings.txt:141449` 有 `CustomCertificateHandler-ValidateCertificate0` —— 这是**无命名空间**的类 `CustomCertificateHandler` 重写了 `ValidateCertificate`。**游戏的证书校验在托管层，而托管代码在 libil2cpp 里，libil2cpp 没有 hash pin。**
- 前置：libil2cpp **没有任何 `il2cpp_*` 导出符号**（`.dynsym` 2660 项、2352 defined，`il2cpp_*` = 0；241 个名字只是 `.dynstr` 里的残留、无人引用）→ `dlsym` / `xdl_sym` 拿不到 API。
- 可行路径：**运行期 dump 解密后的 metadata**（进程里的已经解好，magic 正常）→ `methodIndex` → `methodPointers` → 换算文件偏移 → 改 8 字节 `mov w0,#1; ret`。
- ⚠️ 这条与 AzusaBA 的能力边界直接相关：**AzusaBA 5.2.5 的 26 个 hook 全部走 `xdl_sym("il2cpp_*")`**。如果它在你这台机器上装不上 hook（logcat 里 `api not found`），就证明符号确实取不到，A4 必须走"运行时 dump metadata"这条更重但唯一的路；如果它能装（`installed=1 slots=3`），拿它的加载日志就能反推出可行的解析方式。**这是一个 10 分钟的判定实验，值得排在 A4 前面。**

**A5 · 直接改 `ServerInfoConnectionGroupData.get_ApiUrl` 的返回值** — 成本 M，成功率 中
- 作用：跳过 state，直接把业务 API 基址换成我们。缺点：维护中判定（`State==1`）还在，客户端仍会停。
- 适合作为 A1 成功但 state 拿不到时的补丁。

**A6 · 找到 scheme 并改成 `http`** — 成本 **L**，成功率 低，**建议放弃**
- 就是为了省掉 TLS。但**控制 `/api/state` 响应后 `Servers` 的 scheme 由你决定**，收益完全被 A1+W3 覆盖。没必要为了等价收益去啃 AES/拼接。

**A7 · 用 AzusaBA 的底座做"模块内重定向"（免改 APK）** — 成本 M~L，成功率 中
- 可搬的只有：`xdl` + `il2cpp_boot`（`dladdr().dli_fbase` 取基址）+ `getaddr(..)→methodPointer` + `PtrHook`（指针槽改写 / keystone 现场 trampoline）+ `Syscalls`。
- **它自己的网络层是 0 行**（`connect|getaddrinfo|SSL|cert|UnityWebRequest` 全 0 命中），所以重定向要我们自己写。
- 价值在于：**它是唯一"不改 APK 也能在游戏进程里执行代码"的载体**，天然绕开 ACE 的 `sourceDir` 完整性面。代价是需要 LSPosed/root。

**A8 · 按端口兜底拦截（上游原话）** — 成本 S，成功率 中
- mitmproxy 脚本里的兜底逻辑：*"Redirect any connection on port 5100 to our local gateway, **regardless of the destination host** … the game uses its hardcoded Nexon gateway fallback."*
- 移植到我们这边：**`connect` 桩里不判断主机名，只判断端口**。你现在的 v20 桩只认 `gs` 前缀 —— 而 `state-api` 不命中。**改成"端口 443 全拦"比对域名简单且不会漏。**

### B 组 · 服务端（全部不依赖客户端，可今天开工）

**B2 · 入口形态对齐** — 成本 M，成功率 中，**需要一条真实报文**

**B4 · 玩法表落地** — 成本 L，成功率 中

**B5 · 卡密 token ↔ `AccountServerId` 接线** — 成本 M，成功率 高

### D 组 · 方法论（比技术更省时间）

**D1 · ACE 记账复位必须写成实验前置步骤** — 成本 S，收益 高
- §4.2 已经证明判定会持久化。你现在的记录里出现了**同一改法"有时活有时死"的矛盾**（E30 打 libunity 补丁"不崩能进游戏"，E36 同补丁 SIGBUS）——这大概率是记账污染，不是概率。
- 规矩：每次实验前 `rm` 四个文件 + 记录 `dumpsys activity exit-info`，否则结论不可复用。

**D2 · 先判 RELRO，再选写入方式** — 成本 5 分钟
- `grep libunity.so /proc/$PID/maps`。若 GOT 页是 `r--p`：进程内要先 `mprotect(PROT_READ|PROT_WRITE)`（对 file-backed private 映射合法，不触发 execmod），写完可以不还原。若真是 `rw-p`，你原来的 `str` 就对。
- 这条决定 A1 是"5 分钟下班"还是"又一个 SIGSEGV"。

**D3 · 等官方开服抓一次完整 HAR** — 成本 0，收益 最大
- 你手里那份 HAR 是**维护期**抓的（`State:1`），所以 57 条里只有 1 条 `gsqc-api`、0 条业务包。
- 开服后一次完整登录抓包，可一次性消掉：W4（真实 path/body）、B3（握手是 RSA 还是明文）、region label、`Servers` 完整字段。**比再逆一百小时有用。**

## 5. 关键技术方案（可直接照做）

### 5.1 `connect` 改写的最小可行版（含全部已知修正）

```
落点：libunity 的 connect GOT 槽  0x13d95d8
      （3 个调用点 0xc036f8 / 0xcb4720 / 0xcf50c8 + 1 处直接读 GOT 0x454788，全覆盖）
基址：dl_iterate_phdr 的 dlpi_addr（实测 == maps 里 r-xp 00000000 那行），
      不要用 maps 第一行（存在两个 offset=0 映射）
写入：先判 RELRO（D2）；r--p 则 mprotect(RW) 后写
桩内：
  1) 局部标签 Lb0（不要 .globl 符号，adr 会取 0 —— fault 0x1c20 就是这个）
  2) 保存 x29/x30（tail-call 前必须，blr 会踩 LR）
  3) 读 x0 -> sockaddr：
       AF_INET  (sa_family==2):  [x0+2]=htons(PORT)   [x0+4]=0x0100007F   (127.0.0.1)
       AF_INET6 (sa_family==10): [x0+8]=0              [x0+16]=0x0100007F_FFFF0000
  4) 原函数指针存 libil2cpp RW 段（文件尾之后到 memsz 之间，如 base+0x10300000），
     不要存代码段（代码页只读，§4.8 实测 SIGSEGV ACCERR）
  5) tail-call orig，且 orig 用 dlsym(libc) 或直接读 libil2cpp PLT 0xf2c1060
过滤：不要按主机名（你现在的 `gs` 前缀会漏掉 state-api）；按端口 443 全拦（上游兜底做法）
验证：写后回读 GOT 一致 + `ss -tnp | grep <pid>` 看 443 落在 127.0.0.1
```

### 5.2 TLS：先"测"再"攻"

**不要先写绕过。先花 20 分钟确认这堵墙有多高。**

| 级 | 实验 | 成本 | 若放行 | 若拒绝 |
|---|---|---|---|---|
| L1 | 系统 CA（root）+ `res/xml` 加 user trust-anchor | 20 min | Unity 走系统 CA → **W2 消失** | 说明用内置 CA 包 → L2 |
| L2 | 系统 WiFi 代理 + 自签 `*.bluearchive-cn.com` 证书（**无需任何注入**，你已确认客户端走 7890 代理） | 20 min | 同上 | → L3 |
| L3 | `CustomCertificateHandler.ValidateCertificate` → `return true` | 1~2 天 | 闭环 | → C1 换标的 |

L2 的额外价值：**一旦放行，mitmproxy 直接给出真实业务报文**，等于 W4/W6/B3 一起解决。

### 5.3 伪造 `/api/state`（B1 的落地形状）

```http
GET/POST /api/state
  → 200 application/json
  {"Servers":["http://127.0.0.1:5000/api/"],
   "State":0,"Msg":"",
   "CallbackUrl":"",
   "CustomerServiceUrl":"",
   "AddressablesCatalogUrlRoots":["https://static.bluearchive-cn.com/prodm39"]}
```

- `State` 必须 0（1 = 维护中，客户端不往下走）
- `Servers[0]` 用 `http://` → 后面全链路明文，**TLS 只需解决这一个请求**
- `AddressablesCatalogUrlRoots` 指官方 CDN（无鉴权），省掉重做资源
