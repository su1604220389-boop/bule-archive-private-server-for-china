### 2.3 报文格式（**改包/造包必看**）

**请求**（客户端 → 桥）：`Content-Type: multipart/form-data`，字段 `protocol` / `encode`（`gzip`）/ `packet`

```
packet = base64( [u32 LE 声明长度] + gzip( IV16 + AES-CBC密文 + KEY32 ) )
```

```
body   = base64( AES-256-CBC(明文) + KEY32 )      IV 固定 b"JOSYdf8ys97uhFYS"
明文   = {"protocol":"<名字>","packet":"<内层 JSON 字符串>","requestid":...}
```

### 2.6 桥的两种处理方式（看懂日志的前提）

- **吸收（stub / handled）**：桥自己生成回包，**不进 Shittim、不出现在 wire 里**。日志标记 `relay2_ft=handled-<协议号>`。
- **转发（relay2）**：桥把请求打到 Shittim 5000 再把回包套信封。哪些协议走哪条由**代码常量** `RL2_HANDLED`（`account_auth_probe.py:5103-5105`）决定；改了必须重启桥。而 `cn_*.txt` 这类开关是**每请求现读**，改完不用重启。
- 失败兜底：Shittim 报错时桥会**回落到固定大小桩包**（`relay2_ft=session-retry-failed`），客户端仍收 200——**所以「nginx 全 200」不等于「服务端没报错」**。

证据：`ITEMLIST_RELAY_V2.md` §1、§4；`RECRUIT_LOG_FORENSICS_20261119_0124.md` §5-Q3、§5-Q4。
